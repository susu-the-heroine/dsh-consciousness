# 0.5.0 改进单（三件，按顺序做）

> 写于 2026-11-13 晚。**0.4.1 只修 memory_count，不掺这些。**
> 这张单子管 0.5.0。每一条都必须先写清"怎么验"，验不了的不开工。

---

## 一、能带走：把导出的 Markdown 读回来

**为什么**：现在只能导出，不能导入。人不敢把重要东西交给一个拿不走的地方。

**做什么**：一个导入入口，读 `memory_export` 写出来的那批 `.md`，解析回条目，写进指定识海。

**怎么验（能失败的那种）**：
1. 造一个沙箱海，放二十条，导出。
2. 全删，再导入。
3. 数：进去多少条、丢掉多少条、字段（日期、置信度、别名、类型）对上几条。
4. **判据：二十条一条不少，字段全中。少一条或错一个字段，算没成。**

**失败长什么样**：条目数对但日期全变成今天；或者别名丢了；或者正文里的换行被吃掉。

**不做**：不自动合并去重，不做"导入到已有库"的智能判断。先只支持导入到空海。

---

## 二、准入收紧：负例别再当命中

**为什么**：三十三条负例还有七条被当成命中。问题是放进来的太松，不是排得不好——上次调三组权重，头名一条没动。

**做什么**：改门槛，不改名次。具体先测再定，候选做法是"两路都点头才算命中"：字面一路、语义一路，任一路很弱就压下去。

**怎么验（能失败的那种）**：
1. 固定一份题：三十三条负例 + 正例若干，存进仓库当基线。
2. 改之前跑一遍，记下命中数和误命中数。
3. 改完再跑，**要求误命中降到三条以下，同时正例命中不掉超过两条。**
4. 只降误命中、把正例也砍了的方案，不算成。

**失败长什么样**：误命中断崖式下降，但正例也跟着掉——那是把门槛焊死了，不是修好了。

**不做**：不加新的开关给用户选。开关是后门，用户不该做功课。

---

## 三、候选箱：拿不准的先别进主库

**为什么**：现在要么记、要么不记。缺一个中间态，人不敢让它自己判断。

**做什么**：写入时判断置信度，低的进候选箱，不进主库检索。候选箱要能看、能转正、能扔。

**怎么验（能失败的那种）**：
1. 灌五十句闲聊脏输入，看有几条被塞进主库。
2. **判据：主库新增不超过五条，候选箱有东西，转正和丢弃都能用。**

**失败长什么样**：候选箱攒了几百条没人看——那就是垃圾场，不是候选箱。

**不做**：不做自动转正。转正必须有人点头或者有明确的重复出现证据。

## 2026-11-15 凌晨实测补充（决定下一版先做哪个，看这里）

已经不成立的猜测：

- "没装模型包就不能用"——实测不成立。没有向量文件时会降级成直扫，照样找回目标，还会在回复里
  标一句"这次是凑出来的"。`scripts/no-embed-test.mjs` 把这条固定住了。
- "换个问法就搜不到"——实测不成立。加问号、加"请问一下"、逐字加空格、去掉疑问词，
  二十题里结论几乎不变（最差一档也有一题翻盘）。`scripts/query-noise-test.mjs` 守着。
- "纠正三件套没测过"——现在三件都测了：批注进 notes、可信度压到 0.3 以下、时间钉死后字段变，
  三条都不动正文。`scripts/correction-test.mjs`。

还成立的，按值得做的顺序：

1. **第一名六成五**，两套题一致（57 题调参集 / 20 题留出集）。要往上，只有三条路：
   真实问句覆盖、换重排、或者接受"递几条"。
2. **跨海不关联**：两个海互相看不见，这是产品空白，不是 bug。
3. **图和文件不进记忆**：只认字。
4. **写库语义没统一**（拒写还是照写），要改十来个调用方。
   顺带一个具体的：**已经改了**。走 store-js 的那几件——批注、字段补齐、旧库迁移——原本等锁 120 秒；写记忆和网页保存走的是另一套锁，本来就只等 3 秒。
   2026-11-15 凌晨把那 120 秒也改成 3 秒，超时给的是人话（"这边正被另一个操作占着，稍等一下再点一次"），
   不再把英文 `timeout` 甩到页面上。实测：被占时 3.0 秒回话，放开后 1 毫秒拿到锁。
   守着它的测试是 `scripts/lock-web-test.mjs`，已挂进自检。

别做的：

- 别给个别问句补别名抬分（上次自动别名从 45% 掉到 35%）。
- 别动 minScore 来"看起来更准"——它只挡"相关"那一段，档位越高质量越像没记住。

## 已确认的缺口：五条记忆写了却搜不到（2026-11-15 凌晨）

主库里有五条（#127 #129 #138 #143 #144）正文在、FTS 索引里也有，但没有向量。
实测：拿标题原句去搜，十条结果里都排不上——等于写了看不见。

进度（11-15 凌晨再往下挖了一层）：全文索引那一路是**真找得到**的——拿标题原句去查 FTS，
命中的就是这几条。丢在排序那一层：语义那一路只遍历"有向量"的条目，没向量的在打分时等于缺席，
字面分又不够压过别人，于是排不进来。所以问题不在索引，在"缺向量就该有个字面兜底分"。

补不上的原因：`scripts/vector-gap.mjs` 能查、也能调补，但它离线跑时拿不到向量模型，
`ensureVectorFor` 一律返回 false。向量必须在插件进程里算。

要修的两条路（白天定）：
1. 插件启动时对"有正文、没向量"的条目做一次补齐（异步、限量、失败不吵人）。
2. 或者给检索加一条兜底：没向量的条目按字面分参与排序，保证"写了就能搜到"。
   第 2 条更稳，改动在检索层，不依赖模型能不能加载。

`scripts/vector-gap.mjs` 留着，作诊断用；它查出来的数字跟 `search-doctor` 的向量覆盖率对得上。

## 另一件不是 bug 的（省得以后又去改）

镜像（SQLite）跟 JSON 的"强度"会差一截，今晚实测 34 处，比如 #38 JSON 9.4999 / SQLite 9.3999。
原因是检索一次就强化一次强度，只写 JSON、不回写镜像——这是设计里的"可漂移"，不是坏。
回归原来把这项也要求归零，一读库就变红；2026-11-15 改成只认前三项（多/少条、结构不一致），
漂移只打印一行提示。别为了让它归零去回写镜像，那会把每次检索都变成一次写盘。

**动排序前的基线（11-15 凌晨实测，改完照这个对）**
- 留出集 20 题：前三 16/20，误命中 0/25。
- 调参集 57 题：第一名 37、前三 46、前十 52（此前量的，改完重跑一遍确认没掉）。
- 跑法：`node scripts/eval-sweep.mjs`；留出集那条没有独立脚本，参考 eval-sweep 里的豁免线输出。

**换说法实测（11-15 凌晨 02:00）**：对那几条缺向量的，换了三种说法去问——0/3 全没捞到。
所以现在的字面兜底只救"原句/标题"这一类问法；真要把它们变成能用的记忆，还是得补向量。
别用放宽兜底去凑，会带误命中。

## 更正（2026-11-15 02:00）：那五条不是丢了，是被归档了

半夜我先写"五条有正文没向量、搜不到"，后来又追了一层，发现它们**全部 archived=true**——
是沉降/归档把它们收起来了，按设计就不进检索，只能 restore 回来。所以：
- 不是 bug。`vector-gap` 和自查脚本原来把归档也算进"缺向量"，是我算错了口径，已改成只算在用的。
- 现在主库"在用 215 条，向量 215 条，缺 0"。原始那句话收回。
- 那条"字面兜底"改动留着：不亏，它保证"标题原句一定搜得到"，且已加了反向测试（无关问题不许乱塞）。
- 真正要留意的是另一件事：**它们是什么时候被归档的、要不要捞回来**。捞回来用 `memory_archive restore`，一条一条来。
