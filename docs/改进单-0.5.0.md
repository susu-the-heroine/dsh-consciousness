# 0.5.0 改进单（三件，按顺序做）

> 写于 2026-11-13 晚。**0.4.1 只修 memory_count，不掺这些。**
> 这张单子管 0.5.0。每一条都必须先写清"怎么验"，验不了的不开工。

---

## 一、能带走：把导出的 Markdown 读回来

**为什么**：现在只能导出，不能导入。人不敢把重要东西交给一个拿不走的地方。

**做什么**：一个导入入口，读 `memory_export` 写出来的那批 `.md`，解析回条目，写进指定识海。

**怎么验（能失败的那种）**：
1. 造一个沙箱海，放二十条，导出。
2. 全删，再导入。
3. 数：进去多少条、丢掉多少条、字段（日期、置信度、别名、类型）对上几条。
4. **判据：二十条一条不少，字段全中。少一条或错一个字段，算没成。**

**失败长什么样**：条目数对但日期全变成今天；或者别名丢了；或者正文里的换行被吃掉。

**不做**：不自动合并去重，不做"导入到已有库"的智能判断。先只支持导入到空海。

---

## 二、准入收紧：负例别再当命中

**为什么**：三十三条负例还有七条被当成命中。问题是放进来的太松，不是排得不好——上次调三组权重，头名一条没动。

**做什么**：改门槛，不改名次。具体先测再定，候选做法是"两路都点头才算命中"：字面一路、语义一路，任一路很弱就压下去。

**怎么验（能失败的那种）**：
1. 固定一份题：三十三条负例 + 正例若干，存进仓库当基线。
2. 改之前跑一遍，记下命中数和误命中数。
3. 改完再跑，**要求误命中降到三条以下，同时正例命中不掉超过两条。**
4. 只降误命中、把正例也砍了的方案，不算成。

**失败长什么样**：误命中断崖式下降，但正例也跟着掉——那是把门槛焊死了，不是修好了。

**不做**：不加新的开关给用户选。开关是后门，用户不该做功课。

---

## 三、候选箱：拿不准的先别进主库

**为什么**：现在要么记、要么不记。缺一个中间态，人不敢让它自己判断。

**做什么**：写入时判断置信度，低的进候选箱，不进主库检索。候选箱要能看、能转正、能扔。

**怎么验（能失败的那种）**：
1. 灌五十句闲聊脏输入，看有几条被塞进主库。
2. **判据：主库新增不超过五条，候选箱有东西，转正和丢弃都能用。**

**失败长什么样**：候选箱攒了几百条没人看——那就是垃圾场，不是候选箱。

**不做**：不做自动转正。转正必须有人点头或者有明确的重复出现证据。
