# 检索：三次实验的实测数字（2026-11-14 夜）

数据集：`scripts/data/recall-holdout.json`，50 条正向 + 25 条反例。
正向里 30 条是当晚新出、出题时只看了标题、没看别名。
海：`main`，214 条记忆。

## 三组对照

| 做法 | 头名@1 | 前三@3 | 前十@10 | 反例过线 |
|---|---|---|---|---|
| 原样（纯向量） | 46% | 68% | 90% | 5/25 |
| 硬闸：没共现就不许进榜 | 52% | 72% | 92% | 3/25 |
| **软闸：没共现的压到 55% 分** | 52% | 72% | 94% | 3/25 |
| 稀有词闸：只认覆盖 ≤5% 的词 | 56% | 80% | 90% | 2/25 |
| **稀有词 + 意图闸（当前最佳）** | **56%** | **80%** | **90%** | **1/25** |

结论：软闸比硬闸好——精度一样（反例都是 3 条过线），召回更高（前十 92→94）。
硬闸会把"换了说法"的一并封杀，软闸只是压分。

再往后两步：只认稀有词（一个词在库里覆盖 ≤5% 才算证据），反例 3→2；
再加意图闸（问句是"推荐/买/怎么装"这类操作型、记忆标题是"成了/跑通"这类记录型 → 再压一半），反例 2→1。
正向指标没掉：头名 56、前三 80、前十 90。

重跑：

```
node scripts/eval-holdout.mjs   # 原样
node scripts/eval-cooc.mjs      # 硬闸
node scripts/eval-soft.mjs      # 软闸
```

## 还没解决的

1. **反例还剩 3 条过线**：`推荐一张两万以内的显卡`（0.578 #217）、`Python 怎么装环境`（0.631 #198）、`帮我把这段话改短`（0.551 #211）。它们和某条记忆共享了真实词（显卡 / Python / 改短），共现闸拦不住。
2. **情绪+时间那条路还没做**：用户说"我那天不开心"但不说日期时，应该按时间倒序 + 情绪极性捞候选递给他认领，而不是靠词匹配。这条路没测过。
3. 头名 52% 还没到能用"按重要度只递一条"的程度，现在靠递前十活着。

## 踩过的坑

- `eval-recall2.mjs` 读的是 `recall-set-v2.json`（57 条，调参用），不是留出集。之前那个 70% 是调参集上的数，不能当泛化指标。
- 只加阈值没用：`lib/gate.js` 注释里写着，阈值、两路一致、关键词覆盖率三条都分不开那四条假答案。
- 反例在数据里的写法是 `want: null`。


## 意图分类接进去以后

`lib/intent.js` 替掉了注入里原来那条临时正则（`/推荐|买|怎么装…/`）。
注入逻辑现在是三层叠着：

1. 向量找候选
2. 稀有词把关（命中词必须在库里稀，才算证据）
3. 意图把关（问句是"要东西"、候选是"记录型" → 再压一半）

第三层只认分类器**确定**的 op；说不清不动分。
理由见 `docs/意图分类方案.md`：通用盲测里错的四条全是"说不清"，
让它们落空，比误判安全。


## 2026-11-15 凌晨重新量的两个数（同一份库：220 条活着的、215 条有向量）

| 题集 | 题数 | 命中@1 | 命中@3 | 命中@10 |
|---|---|---|---|---|
| 调参集 `recall-set-v2.json` | 57 | 37 (65%) | 46 (81%) | 52 (91%) |
| 留出集 `recall-holdout.json` | 20 | 13 (65%) | 15 (75%) | 20 (100%) |

两套题上 @1 都是 65%，说明这个数不是调参调出来的假象。
但留出集只有 20 题，一个题就是 5 个百分点，别拿它当精确指标。

没进前十的有两条，都查过原因：

- 「我的名字哪来的」想要 #95《你赠予我的"名字"》，那条里"名字"出现太多次，被别的条目分走；
- 「我的形象是什么样的」想要 #55《大肥鱼的视觉密码》，别名是"大肥鱼长什么样才算对"，跟"形象"不搭。

**没去补别名。**补上这两句就能刷到 67%，但那是照题作弊——
上次自动生成别名已经从 45% 掉到 35%，同一个坑不踩第二次。

要真的往上走，只有三条路：真实问句覆盖、换重排、或者接受"递前十"这个档位。
