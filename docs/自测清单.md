# 识海 · 发版前自测清单

> 每次发版前照这条走一遍。**机器能查的跑 `node scripts/preflight.mjs`，人必须点一遍的看下面。**

## 一、机器查（一条命令）

```
node scripts/preflight.mjs
```

九项：版本号、files 齐全、必需文件、没有备份文件、CHANGELOG 版本、页面语法、页面资源、插件语法、零依赖。
任何一项不过就不许发。

## 二、人必须点一遍

这几条机器查不出来，漏一条就是发半成品。

1. **打开识海**：左侧金圈「识」能点开，画面在动，不是黑屏。
2. **写一条新记忆**：写进去之后，**刷新页面前**看一眼——它有没有自己出现在星图上、有没有进记忆库。
   （这条就是 0.4.5 漏掉的东西：库只在打开时取一次数据。）
3. **记忆库**：工具栏能打开，能搜到刚才那条，点开有全文，左下角数字和库里条数对得上。
4. **三百条**：库里总条数超过 300 时，图上是不是正好 300，多出来的都在库里。
5. **老库**：拿一个条数多的库（上千条）打开，页面不假死、不白屏。
6. **重启 DSH 之后**：记忆还在，页面还开得出来。

## 三、发版

```
node scripts/preflight.mjs && npm publish
```

发布后 registry 的 `latest` 标签会延迟几分钟才更新，**不是没发上去**，别再重复发——重复发会因为版本号已占用报 409。

## 手动改过 data.json 之后

镜像（memory.db）不会自己跟着。批量补别名、改字段这类手动操作跑完，补一步：

```
node scripts/sqlite-import.mjs main
node scripts/sqlite-parity.mjs
```

第二行走完，四行数字都得归零：

- 只在 JSON 里：0
- 只在 SQLite 里：0
- 结构性不一致：0 处
- 可漂移：0 处

不归零就是没同步上，别当成“没事”。2026-11-14 就是补完别名忘了这一步，整套自测十二组里唯一失败的那一组就是它。

## 回归集：改完东西先跑这一条

```
node scripts/regress.mjs
```

七条断言，全过退出码才是 0。每一条都对应一次真踩过的坑：

1. 发版前检查全过（含 profile 启用清单——2026-11-14 插件装了不出现在界面上，就是它被抹了）
2. 健康探针自动找端口且九项全过（端口写死会误报一堆失败）
3. 镜像与 JSON 四个数归零（手动改库后忘了同步）
4. 读实体先读 entities，单数只许当兜底（读错名字，报出"实体覆盖 0%"）
5. 写库回执带别名提醒
6. 稀有词表建在循环外（写在循环里，库一大就退化成平方）
7. 分类器与标注集齐全，且 lib 在打包清单里

以后修一个新问题，就往这里加一条。加的不是文档，是断言。
