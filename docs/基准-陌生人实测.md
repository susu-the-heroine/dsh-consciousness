# 陌生人基准实测（2026-11-14 夜）

**它测的不是"咱俩"，是"别人装上以后还灵不灵"。**

六个互不相干的人，每人六十条记忆（其中十二条是"同一台机器、同一个房东、不同一次"的硬干扰），
每人二十四道题（正着问 / 带错字 / 绕着问 各八道），一共三百六十条记忆、一百四十四道题。
全部在内存里算，不碰任何真实识海。

跑法：`node scripts/bench-synth.mjs`（约十秒；加 `--misses` 会列出没进前三的题）

## 一、合计

| 档位 | 题数 | 纯向量 @1/@3 | 字面+向量 @1/@3 | 差 |
| 正着问 | 48 | 98 / 100 | 98 / 100 | +0 |
| 带错字 | 48 | 85 / 100 | 98 / 100 | **+13pp** |
| 绕着问 | 48 | 92 / 100 | 88 / 96 | −4pp |
| 合计 | 144 | 92 / 100 | 94 / 99 | +2pp |

随机基线：@1 = 1.7%（1/60），@3 = 5.0%（3/60）。

**一句话：字面这一路真正救的是"打错字"，救得很硬（区间 [+4.2, +22.9]，不跨零）；
在"绕着问"上它是拖累（−4.2pp，但区间跨零，不能当结论）。总差 +2.8pp，区间跨零。**

## 二、换个人还灵不灵（留一人验证）

六折全部选中「字面+向量」（纯向量 0 次）。留出的那一个人身上：选中配置一百三十七道中一百四十四，
纯向量一百三十三，融合一百三十六。选中那个比另一种好 4 次、差 1 次、平 1 次。

**结论：五人投票选出来的配置，搬到没见过的第六个人身上也站得住。** 这是"别人也能用"最直接的那条证据。

## 三、六个人各自

咖啡店主 83/96 · 汽修工 100/100 · 高三学生 96/100 · 养狗的人 92/100 · 独立开发者 100/100 · 医院陪护 96/96

两个满分的人（汽修、开发）不是模型强，是他们的每条事实都带唯一数字或型号（P0299、640、Node 18→20），
两路都能靠锚点锁死。**要压下来只能把题改成没有唯一锚点的问法，那就成了真歧义，不干。**

## 四、真丢的三道（头名没中，但都在前三）

1. `[带错字] 瑞幸现在一杯多少前` → 该中「瑞幸降到八块八」，两路都排第二，头名都是「隔壁开了瑞幸」（9.9 对 8.8）。
   **同一件事有两个版本，新的那个没被认出来。** 这是时间更新问题，不是检索问题。
2. `[绕着问] 有人想让我只上他们一家平台，给了什么条件` → 该中「美团来谈独家」，融合第四。
3. `[绕着问] 有人嫌它吵，我买了个没怎么用的小玩意` → 该中「门铃一响就叫」，融合第三、向量第二。

## 五、这轮量出来的两件待办

1. **同事实的两个版本，得让新的赢。** 库里其实有 `born` / `lastSeen`，冲突时优先新的就行。
   但这个基准的记忆里没有时间字段，所以这条在这儿测不了——要么给基准补时间，要么去真库上量。
2. **绕着问仍然是融合最弱的一档**（88/96）。和自家库里那个结论一致（见笔记补六十七）：
   缺的不是排序公式，是"口语指代 → 库里说法"的桥。

## 六、库大了还来不来得及（规模实测）

`node scripts/scale-bench.mjs [识海] [题数]`，只读 data.json。

- 一千零九十二条：单轮中位 **9 ms**，九成线 266 ms（第一轮要建片段缓存）
- 两千九百六十四条：单轮中位 **11 ms**，九成线 **15 ms**
- 建向量是一次性成本：一千条七十五秒、三千条两百零五秒，之后写盘复用

我第一版量出来是"三千条五百五十三毫秒"，那是错的——我在每轮里对每条记忆重算了一遍片段，
线上早就缓存好了。差一个缓存，数差六十倍。这条已写进笔记补六十八。
