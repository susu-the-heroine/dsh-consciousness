# 已知限制：问「细节值」时会被邻条顶上

2026-11-21 夜查出来的。八个版本都想在检索出口加一道闸，每次都把正常问句一起拦掉，全部撤回。
结论：这不是漏了一行判断，是检索结构里没有「值」这一层。要治得做值/属性抽取，工程量大，收益只有四个样本——按苏苏侠那晚的话，先不做。

## 现在会答错的样子

| 问句 | 现在 | 应该 |
|---|---|---|
| 那辆自行车换了什么轮胎 | 列出自行车相关两条 | 自行车记着，轮胎没记过 |
| 冰箱里那盒酸奶过期了没 | 列出不相干两条 | 没这回事 |
| 他第一次坐飞机是哪一年 | 列出一条带年份的 | 没记过 |
| 阳台上那盆花浇多少水 | 反问确认别的条目 | 没这回事 |

## 量它的工具

    node scripts/eval-human40.mjs

当前：正题四十条对上三十六、误拒零、答偏四；反题十条（库里真没有的十个词）老实拒六、硬答四。

## 别再做的方式（八版都试过）

1. 全库没有属性词就拒 → 拒的话不被认成拒，反把一条老实拒算成硬答
2. 按条筛属性 → 那四条不走这段代码
3. 出口处按条筛 → 同 2
4. 问值且几条里没数字就拒 → 条目里到处是数字，判据形同虚设
5. 稀有词全库为零才拒 → 挑出来的是「那辆」「次坐」这种词内碎片
6. 实词全库为零才拒 → 反题 9/10，但自检掉到 119、灰区掉到 14
7. 头一条零重叠就拒 → 反题 9/10，自检 118、灰区 13
8. 问值且头一条零重叠 → 自检 121、灰区 14

每一版都先跑 `node scripts/guard.mjs`，八次全被它拦下——这条护栏是今晚最值的产出。
