# 意图分类：方案

## 它解决什么

留出集里还剩一条误命中：`Python 怎么装环境` → 撞上「真装一遍成了：掐掉 Python 后语义分还在」。

两边都真有「Python」，也都真稀有。字面判断到此为止——一条是在**要东西**，一条是在**说事**。

所以要做的是判断一句话属于哪一类，不是继续调阈值。

## 分几类

只要两类半，别贪多。

1. **要东西**（operational）：推荐、买、装、选、在哪下、多少钱、怎么写代码。
2. **说事**（narrative）：成了、跑了、当时、记得、那次、后来。
3. **说不清**（unknown）：两句都不像。默认按"说事"处理——记忆系统宁可多给上下文，也别装懂。

## 怎么判

先规则，后模型。规则够就不上模型，模型要训练要权重，装进包里是负担。

规则要看这几样：

- **动词形**：「怎么装」「怎么选」「推荐」「买」「下哪个」——操作型动词短语。
- **疑问代词**：「什么、哪个、多少、哪里」+ 名词，多半是要东西；单独一个「吗」不算。
- **时间/回忆词**：「当时、那次、那天、后来、后来才、记着」——说事。
- **完成体**：「成了、跑通了、定了、上线了、修好了」——说事。
- **主语**：说「我/你」+ 过去的事 → 说事；说「我要/帮我」+ 动作 → 要东西。

## 判错怎么办

只用来**压分**，不用来封杀。

- 判成"要东西"、候选又是记录型的（标题含「成了/跑通/定了」）→ 分乘 0.5。
- 判成"说事"→ 不动。
- 说不清 → 不动。

这样即使判错，最坏结果是某条记忆名次掉一点，不会让它消失。

## 验收标准

数据：60 条真实问法，一半操作型一半说事型，人工标。

- 分类准确率 ≥ 85% 才准接进注入。
- 接进去以后，只在**留出集**上看：反例过线条数要 ≤ 1，正向头名不能低于 56%。降了就回退。

调参用一套，验收用另一套。两边混着用，等于自己给自己出分。

## 已知边界

- 「他手机号多少」是要东西，但库里根本没有——分类对了也找不到，这类靠反例压分。
- 「那个显卡的事后来怎么样了」是混合句，先按说事处理。
- 这层永远救不了「我记得但库里没写」——那要靠写入侧补。


## 实测（2026-11-14 夜）

规则分类器写在 `lib/intent.js`，验收脚本 `scripts/eval-intent.mjs`。

- **调参集**（64 条，苏苏侠的语境）：96.9%（62/64）
- **他语境的盲测**（20 条，出完直接跑）：70%
- **通用盲测**（20 条，跟他的生活无关）：80%

三组差距说明一件事：这套规则吃的是他那种问法。换成别人随便一聊，
"明天去北京要带什么""怎么跟老板提涨薪""有没有不辣的做法"全落进"说不清"——
因为它们没有"推荐/买/怎么装"这类强信号。

所以接进注入时只用它**确定**的那一档：判成 op 且候选是记录型才压分；
说不清一律不动。这样通用盲测那四个错都落在"不动作"上，不会误伤。
