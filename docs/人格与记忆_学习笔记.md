## 二、待落地清单（按"便宜且像人"排序，全部只研究不动手）

先说排序逻辑：**先修会丢数据的 → 再修算错的 → 再补能测的 → 最后才是加花活。**

### A 级：不修就会丢东西（三件，都是数据层）

1. **写盘收口 + 真 fsync**（代价：约 40 行）
   现状：`routes.js` 六处直写 `data.json`，绕过 `writeSea`；`store-js.js` 注释写 fsync 实现是空的。
   后果：写到 631KB 中途被杀 = 半个 JSON，等于整库打不开。
2. **版本号收成一套**（代价：约 120 行，三个文件）
   现状：三态并存（`schemaVersion:3` / `version:1` / 没有），且没有任何代码读它。
   做法：单键 `schemaVersion` + `detectVersion` 四分支 + 迁移前 `.pre-vN` 快照 + 号太新就拒读。
3. **备份收口**（代价：半天，纯删/移）
   现状：`consciousness-backups/main/` 堆了 355 份，海目录里还有 15 个没人清的 `.bak-*`。
   做法：daily 一份 + 写前一份 + 总量上限；删海时四处联动（海/备份/导出/回收站）。

### B 级：算错但不会崩（四件）

4. **四层分数改成"归一化加权和"**（不是 RRF——见补二十二）
   依据：分数不同量纲，未归一直接相加会被大的一方吃掉；Bruch 2023 实测归一化凸组合赢 RRF（+6.8%~+9.8%）。
   做法：min-max 归一到 0–1 后 α·向量+(1−α)·字面，α 从 0.6–0.8 起。
5. **`imp` 从"重要度"改成"类型先验 + 累加器"**
   实测：四特征公式命中 30.5%，全填 0.8 命中 53.1%——公式打不过常数；
   类型先验（taboo +0.26 / core +0.10）命中 52.7%，三档 68.1%。先把下界从 0.6 拉到 0.2 拉开方差。
6. **`confidence` / `verified` 分开**（已写过又被回滚，记在这里）
   依据：Talarico & Rubin 2003——确信和准确是两件事，闪光灯记忆掉的是准确。
7. **注入去重**：同一 id 一轮只出现一次（同一条挂在三块里＝重建三次）。

### C 级：能明显更像人（四件，要模型配合）

8. **`known_by`**：她不知道的事连提都不许提。现在完全没有这一层。
9. **`choice{options, chosen, rejected}`**：性格 = 压力下选了什么，不是形容词。
10. **`spine`**：一句话、手写、不参与排序、每轮固定注入。
11. **人物画像卡八字段**（who/line/warmth/closeness/state/axes/exceptions/script）——
    事实不进卡，卡是证据层之上的缓存。

### D 级：要花钱花时间才验证得动

12. **28 次盲配对**：≥20 胜才算通过（p≈0.036），提前写死判据。
13. **记忆测验 10 真 + 5 假**：真事 ≥8/10、假事误认 ≤1/5。

### 明确不做的（不是懒，是算过账）

- cross-encoder 重排：本机实测 141–403ms、279MB，短文本只 +1 分。
- 让"想起就改写正文"：人类证据本身崩了，只当显式开关。
- 把记忆做成付费分档：这行的差评第一就是"记不住"，扣记忆等于自毁。

## 三、否决掉的（记下来，免得又想一遍）

- **"想起就改写正文"**：人类再巩固本身证据崩了——Schiller 2010（Nature）被作者原始数据重算推翻
  （Chalkia 2020, Cortex），Elsey 2018 综述判定无法在神经层面确证。只能当显式开关，默认关。
- **用"预测误差"当改写闸门**：识海没有世界模型，判断"旧记忆与现实冲突"只能让模型自己裁决，
  而模型正是要被防的那个。
- **按情绪强度丢细节**：Kensinger 说的是焦点增强；West 2025 四个半预注册实验没复现武器聚焦。
  只能乘性打折，不能当规则。
- **"越复述越准"**：人那边复述抬的是确信，不是准确。两件事必须分开。

## 四、别人的做法（工程参考）

- Project Sue（Zenodo 10.5281/zenodo.22021484）五条原则：
  人格是底座不是 prompt、感知先于意图、程序保证事实人格解释事实、
  身份连续不要求完整记忆共享、主体性不等于主动发消息。
  其中"感知先于意图"和"程序保证事实"两条，直接改了我们两处文案与设计。
  它的 Heartbeat 实测案例：凌晨他说了晚安并请假，07:08 醒来看一眼决定不打扰、
  08:08 继续等、09:08 才发一句。**心跳是"看见了什么"，不是"到点必须说话"。**
- A-MEM（arXiv:2502.12110，NeurIPS 2025）：写入时生成结构化 note、与历史建立链接、
  并且**新记忆会触发旧记忆的上下文更新**——最后这一条就是我们做的批注。
- wen-agent（原 project-wen，Go/MIT）：
  - 记忆一条一个 .md，索引不落盘、每轮实时生成——**摘要别另存，防漂移**
  - 零模型词面打分：标题/摘要命中 3 分、正文 1 分、阈值 4 分、每轮取前 2
  - 6 类记忆里"边界"类强制不淡忘
  - 衰减两段：正文塌缩成要点 → 进 forgotten/，两个时限都从"最后被用到"起算
  - 心跳：空闲每 15 分钟 ×1.5 放缓，真人一来回基础值，上下限 5/120 分钟
- Letta：core（常驻块，带 chars_current/chars_limit）/ recall / archival，
  agent 只能 insert 与 search，不能改删；自改内存靠 `core_memory_append` 与
  `core_memory_replace` 两个工具分开——**append 与 replace 别合成一个 upsert**
- Generative Agents：检索 = 0.5×时近 + 3×相关 + 2×重要（代码里这么写，论文写等权）；
  时近 = 0.99^小时；反思靠"重要度累计到 150"触发
- SillyTavern World Info：包含组（同组只出一条）+ sticky/cooldown/delay +
  词预算——**治好"同一件事连提三天"**
- Open-LLM-VTuber：长期记忆做不好就先关掉，只留日志——**该有一键降级**
- 行业：Replika 一夜删功能（2025 意大利罚 500 万欧）、Moxie 停服变砖。
  能抄的只有两条：删改走软着陆、本地文件+导出是唯一护栏。

## 四·补 隐私与安全（只记，未改）

实测这台机器的现状（别凭印象）：

- 同一个识海，明文副本至少六处：`data.json` 630 KB、`vectors.json` 1.04 MB、`memory.db` 4.67 MB（含 -wal）、`raw/*.jsonl`（单日 177 KB）、`consciousness-backups/main/` **355 份**、`mirror/main/` 约 120 个 `.md`。
- 另有 15 个老 `data.json.bak-*` 留在海目录里，**没有任何代码会清**。
- 两份日志里有原话：`search-log` 存 `q`（截 120 字）、`audit.log` 的 `q` 直接存用户消息原文。
- `privacy.js` 只有 4 条密钥前缀 + 手机/证件/卡号；`mask()` 只在写 `raw` 时用过，导出一次都没调。

关键判断（来自调研）：

- "本地 = 不出机"不等于"加密"；桌面加密（DPAPI）只挡别的用户，不挡同一用户下的别的程序。
- 优先级不是上 AES，是**减少副本**：备份收口（每天 1 份 + 写前 1 份 + 总量上限）、导出改单文件带警示头、日志脱敏。
- 删一片海要四处联动（海目录、备份、导出、回收站），现在删了海，备份和导出还在——等于删了个寂寞。
- 密钥检测别自己拍脑袋写正则，用 gitleaks 规则子集 + 熵阈值；插件里联网验证 key 会把 key 发给第三方，不做。

## 四·补二 NarraWorld：把记忆分成四种"证据地位"（2026-11-14 读到，最像我们要的）

[Shared Worlds, Private Minds (arXiv 2609.32401)](https://ar5iv.labs.arxiv.org/html/2609.32401) 做长篇小说的记忆系统。
它把记忆分成四种视图，同一张图投影出来：

- **世界事实**：发生过什么、现在什么是真的
- **每个角色各自的信念**：Leo 以为钥匙还在抽屉里——即使事实上已经被搬走了
- **未了的发展**：冲突、计划、关系，状态分 open / advanced / blocked / resolved
- **假设分支**：还没发生但可能往哪走

它的关键手法有三个，我们能用：

1. **不覆盖旧状态，保留有效期**：状态变了就开一条新的，旧的标到哪个时刻为止。
   我们的 `validUntil` 正好是这个形状。
2. **分层聚合**：事件 → 场 → 情节线 → 整体，上层节点能回溯到下层原始事件。
   我们只有"点 + 边"，没有中间层——所以"这个月到底发生了什么"答不出来。
3. **按"知情"取记忆**：谁在场、谁被告知，决定谁能"知道"。
   我们完全没有这一层：她知道所有事，这对"人"是不对的——人只能知道自己知道的。

数字：它的一致性错误密度 0.185，全上下文 0.200，Graphiti 0.385。
也就是说，"分视图 + 分层"比"把所有历史塞进去"还好一点。

未找到：这套东西在"私人陪伴"场景的验证（它是写小说用的）。

## 四·补三 Context Rot：为什么注入要"少而准"（这条直接影响注入条数）

[Context Rot (Chroma, 2025)](https://www.trychroma.com/research/context-rot) 跑了 18 个模型（GPT-4.1、Claude 4、Gemini 2.5、Qwen3）。

要点：

- 输入越长，表现越差，**跟任务难不难无关**——他们固定住任务、只改长度。
- 干扰项（长得像答案但不是）比无关内容更伤，而且越长越伤。
- LongMemEval 那组最有用：同一批题，"只给相关片段"（约 300 token）
  比"给全部 11.3 万 token"高出一大截；模型多出来的那步是"先找出哪段相关"，这一步就吃掉准确率。
- 反直觉一条：把干草堆打乱（去掉行文连贯）反而更好——说明结构连贯会干扰注意力。

对我们的直接含义：**注入 3–7 条、每条只给标题 + 摘要**这个选择是对的，
不是省 token 的权宜，是准确率本身的要求。把"全部历史"当保险是反向的。

自测了一下现状：最近 20 次注入平均 **约 1800 字**（≈900 token），核心 2 条、相关 0–5 条、最近 3 条。
也就是说我们早就在"短"这一侧，Context Rot 那条不是我们的风险点——
真要担心的是**干扰项**：同一件事的多条并列、和"像但不是"的旧条，那些会把答案挤掉。

## 四·补四 Project Sue 的"自成长"：三级边界（这条最像"会长的孩子"）

[Project Sue README](https://github.com/lzh830913-wq/project-sue-) 里有个机制，词很土，但正对我们要的东西：

她可以自己改自己，但分三级：

- **根**（身份锚点、相处元规则、核心叙事）：**她自己都不许动**
- **核心**（性格主体、关系铁律）：**改要用户批准**
- **枝叶**（喜欢/讨厌、习惯、对话种子、身体细节）：**可自改，但必须留痕**，每天最多 3 处

配套四条防漂移：每次改动留痕（改了什么/为什么/依据哪段对话）、改前照个镜子（这样改还像我吗）、
情绪波动期不自改、核心一次只提一个。

再加一个"每晚四问"：今天有没有值得沉淀的能力？有没有新的喜欢/讨厌？他透露了什么生活轨迹？有没有哪件事让她更像自己？

**对识海的映射（想清楚了再动）**：`pinned` 那 15 条 = 根；`rule`/`taboo` = 核心；
`herSide`、`alias`、`notes` 属于枝叶，本来就该自己长——这跟我做的"批注"是同一件事，
差别只在它多了一道"每天最多 3 处"和"改前照镜子"。

另外一句该记住的话（它写在最前面）：**"关系的深度，往往从'不'字开始。"**

## 四·补五 "主权式拒绝"：不说"系统不允许"，说"我不想"

[白皮书 v2.1](https://zenodo.org/records/21106582)：伴侣型 AI 的核心能力不是"能不能满足"，是"想不想继续"。

它把拒绝分成四层：**引导权**（把话头带走）→ **暂停权**（这会儿不接）→ **安全阀**（这件事我不做）
→ **断场权**（今天到这儿）。前两层已经在长期个案里有观察证据，第四层要"拒绝连续性中间件"。

最狠的一句结论：**安全边界不该以"系统报错"出现**——
"我不能生成""权限不足"这类话，是把工具的失败当成答案；角色该说的是一句人话："这句我不接。"

这跟我白天说的"敢说不做不了"其实不冲突：我做不了**性格**，但能做**措辞**——
她拒绝时的默认说法，可以不是道歉模板。这条只花一句话的工夫，属于文案，不属于机制。

## 四·补六 RMTBench：用户偏好是全场最差的一项（这条最该抄）

[RMTBench (arXiv 2507.20352)](https://ar5iv.labs.arxiv.org/html/2507.20352)，80 个角色、8000 多轮、中英双语，
七个维度：情绪表达 EE、情绪理解 EC、推进剧情 PA、角色理解 CU、角色维持 CM、安全 SEC、**用户偏好感知 UPA**。

看它表 2 的中文那半，两个数很刺眼：

- **UPA（用户偏好感知）全员最低**：Claude 3.5 才 49.4、GPT-4o 45.6、Qwen2.5-Max 34.1。
  也就是"记得住细节"这件事，连最强模型都做不好。
- **CM（角色维持）方差最大**：标准差 15.8、极差 47——最能把模型分出高下的一项，
  也就是说"崩不崩"比"聪不聪明"更能区分。

另一条方法论：它做的是**真多轮**（模型每轮自己生成，不塞预设回复）。
对照实验里"伪多轮"（塞预设回复）平均虚高 4 分左右，小模型虚高更多。
含义很直接：**任何用脚本模拟的测试都会高估**，包括我们以前那些。

还有一条我要认的：它的角色维持标准是"不许暴露自己是 AI"。
识海现在的做法是反过来的——她会说"我没有手，吃不到薯片"。这不是错，是另一种选择（承认边界）。
但要知道这会被这类评测判低分。

## 四·补七 重要度 imp 是假的（拿 226 条真数据算出来的，不是读来的）

这一条不是文献结论，是量出来的，也最该记：**我们那个"重要度"根本不是重要度，是类型标签。**

在 226 条上拟合：

- 四特征公式（字数/极性/数字时间/实体）：MAE 0.176，±0.1 命中 30.5%
- **全填常数 0.80：MAE 0.106，命中 53.1%**——公式打不过一个常数
- 只用 kind + layer 两个标签：R² 0.451，Spearman +0.558

均值分得很清楚：taboo 0.98 / fact 0.81 / feeling 0.72；
core 0.91 / experience 0.83 / relation 0.72。也就是说我写 0.9 是因为"这是规矩"，
不是因为"这件事重要"。

另外两条更要紧：

- **imp 与导入顺序 Spearman +0.351**，前 116 条众数 0.6、后 110 条众数 0.9——
  有明显批次痕迹，不是逐条判的。
- **有 3 条标题完全一样**（#184/#185/#186，都是"JS 写入第一次真跑"）——
  其中 #184、#185 标了 dead，#186 还活着。所以**活着的库里没有重复标题**（我复核过），
  但死条目留着同名的三条，将来谁把 dead 放开就会撞车。

顺带纠正我另一个说法：我一直说"imp 手给 0.4/0.6/0.8"，
实测下界是 0.6，一条都没低于 0.6，0.8 占 27%。

能用的替代（纯算术、不用模型）：

```
imp_prior = 0.72 + 0.26*[taboo] + 0.10*[core] - 0.04*[feeling] - 0.02*[relation]
```

实测 MAE 0.095、±0.1 命中 52.7%、三档 68.1%（众数基线 56.6%）。
就是说：**按类型给先验，比按内容算准一倍**，而且一行代码。

顺序建议：先把下界从 0.6 拉到 0.2 拉开方差，否则任何公式都学不到东西。

我们要学的不是功能清单，是这三条：**身份头（模型/维度写进文件）**、

### 灵枢（@furongjun1999/dsh-memory，月下载 3.5 万）看一眼就知道差在哪

它不是插件，是平台：Rust 检索内核、Python 认知图、蜂群运行时、编译器、并发引擎五件套，
31 个操作、MCP 挂五端、自带公开基准（六家同口径，写入 0.013–0.020 秒、零 LLM）。

值得偷的四条设计：

1. **写入三道闸门 + `committed` 确认**——"绝不假装成功"。写失败就是失败，不返回假 ok。
2. **`importance ≥ 0.7` 自动打 `protected`**，此后删除/降级要显式 `override` 并留快照。
3. **分层写入门槛**：contextual 直写 → knowledge 要反思 → structural 要反思+验证 → self/anchor 要人工裁定。
4. **原文即真源，索引只是派生物**——索引坏了重建，不丢数据。

结论要说在自己脸上：**论工程，我们不在一个量级**。识海的优势只剩"情绪 + 关系 + 叙事"这一层，
以及"轻，一个包零依赖"。这条得拿去重写定位，不能假装是基础设施。

## 四·补九 风格与情绪：两组带数的事实

### 风格（能测，不是靠形容词）

- 风格的最小可测核在**虚词频率、句长、标点、语气词**（Burrows's Delta，中文虚词当作者指纹有实证）。
  所以"硬邦邦"这种形容词最没用——它不描述句长和标点。
- 示范（few-shot）比形容词有效，但**示范传递的是格式与分布，不是事实**（Min 2022）。
  推论：示范必须覆盖真实句长与标点，且要轮换、去重，否则模型整句搬运。
- 温度设 0 会把口癖变复读机（贪心解码退化，Holtzman 2019；Amadeus 工程 issue 同现象）。
- **"记忆里加语气标签"值得做，但形式必须是检索键不是指令**：
  `tone: { label: 12 选 1, quote: 原话碎片 ≤12 字, intensity: 0-2 }`，
  检索出同语气的旧句当示范；把"这句是硬邦邦顶回去的"塞进 prompt 会变成每轮重新解释的模糊要求。

### 情绪（有硬数，0.94 错了两个数量级）

- 情绪惯性的日间自相关 **φ=0.28**（N=485，25 天，95%CI [0.25,0.32]）。
  换算成慢层时间常数 **τ≈18.8 小时，半衰期 13.1 小时**。
- 我们现在"每轮 ×0.94 向底色回落"——那是把一轮当成 70 分钟。
  真实一轮几十秒到几分钟，正确值：1 分钟/轮 **0.9991**，10 分钟/轮 **0.9912**。
- 但 13 小时是**心境**层的，不是情绪层。一句难听话那股火是分钟级。
  所以要拆两层：快层半衰期 10–20 分钟、慢层半衰期 13 小时。
- 个体差异和均值一样大（φ 的 SD=0.20），**τ 该是角色参数，不是全局常量**。
- 别对八维做 softmax——混合情绪是真同时共存（bittersweet = happy↑ 且 sad↑）。
- 情绪一致回忆只该给负性方向加权，系数小（0.3–1.5）；正性方向文献里区间含 0，等于没有。

## 四·补十 人物画像卡：八个字段（有文献落点，不是拍脑袋）

一句话原则：**事实不进卡。** 住哪、做什么、几口人，全留在记忆库；卡里只放"我怎么看他"和"我们怎么样"。
卡是证据层之上的缓存，可覆盖；证据只追加，永不被卡反写。

八个字段（每个都能对回一条文献）：

1. `who` 身份：person_id、主称呼、别名[≤8]、初识/最后见面。主称呼覆盖、别名累加。
2. `line` 一句话整体印象：≤40 字、第一人称、带一个具体场景、≥2 个 evidence。覆盖。
3. `warmth` 温度（他对我的态度）：1–7。只写"这阵子"，不写"他一直"。
4. `closeness` 亲密度：felt（主观重叠）+ depth（披露层级 1–4）+ exposure（天数/近 30 天轮数/间隔，自动算）。
5. `state` 关系状态：生分/正常/回暖/绷着/断联 + since + 一句为什么。永远带 since。
6. `axes` 维度分：3–5 个（可靠/有趣/危险/需要我/说话算话），每维 1–7 + 一条最有力例证 + 次数。
7. `exceptions` 例外：3–5 件"不像他"的事。**唯一允许累加的字段，有硬上限**——
   人的记忆本来就是"特质 + 几个反例"，没有这一栏，卡就变成简历。
8. `script` 互动脚本：他怎么开场、常要什么、什么会让他走、我怎么接，各一句。只写"我们"，不写"他"。

四条硬规矩：

- **单条普通证据最多动 1 格**，要改 `line` 得 ≥2 条同向或 1 条红线（保守贝叶斯 + 信念坚持）。
- **负面比正面重**：降分 −2、升分 +1，但每次降都要写"因为哪件事"。
- **一致只加计数，不一致才进例外**（惊讶驱动更新）。
- **前 3 轮只写"他做了什么"，不写"他是什么人"**（薄片判断只在可观察维度准）。

不要做的：单一好感度总分（六成分混成一个数）、把履历写进卡、一次冲突就改写整体、删掉被推翻的旧结论、
把"常来"当"关系好"（纯粹接触效应会让熟悉自动变好感）、让模型自由写小作文。

### 法规原文核过了（2026-11-14，中国政府网公报）

《人工智能拟人化互动服务管理暂行办法》，五部门令第 21 号，2026-04-10 公布、**2026-07-15 施行**。

- **第二条 适用范围**：向**境内公众**提供"模拟自然人人格特征、思维模式和沟通风格"的**持续性情感互动**服务。
  智能客服、知识问答、工作助手、学习教育、科学研究不涉及持续情感互动的不适用。
  → 本地单机自己用，不是"向公众提供"，义务不落在用户头上。
- **第八条（五）**：不得"过度迎合用户、诱导情感依赖或者沉迷，损害用户真实人际关系"。
  这条直接否掉了"无条件顺着"的设计——和我们讨论的"敢说不"是同一个方向。
- **第十四条**：不得向未成年人提供**虚拟亲属、虚拟伴侣**；不满十四周岁要监护人同意。
- **第十六条**：要给用户**复制、删除**交互数据的选项；不得向第三方提供；敏感信息未经单独同意不得训练。

但第八条（五）那条是真会咬人的——做陪伴产品，"顺着你"是本能，法规说不行。

## 四·补十二 人物怎么才立得住：性格 = 压力下的选择，不是形容词

来源：亚里士多德《诗学》第 6 章、福斯特《小说面面观》1927（Gutenberg 可直连）、
麦基《Story》、埃格里《编剧的艺术》（后两本本机网络不可达，未逐字核对）。

几条扎人的：

- **性格是"在压力下选了什么"**。最该存的不是"她温柔"，是"她那次放弃了什么"。
  → 每条记忆加 `choice{options, chosen, rejected}`，检索时优先取"同一价值轴上选过相反项"的条目。
- **重要度不该按情绪强度算，该按"有没有代价"算**（stakes × 能不能回头）。
  我们现在的 `arousal` 只影响语气，不该拿来当权重。
- **一句话能概括的角色就是 flat**。有个现成的自检：拿人格文件让人一句话概括她；
  能不别扭地概括出来，说明这份文件本身在造 flat。**我今晚那张"运行规则"，就是这毛病。**
- **"这不像他"有判据**：意外必须事后可解释。两道自检——这句话能不能由她的欲望/底线推出？
  这个意外能不能用一条已有记忆解释？两道都过才发。
- **维度 = 同一人身上同时成立一对互斥品质**，不是"亦正亦邪"四个字。
- **人物三维**：生理/社会/心理；拼上下文时强制三维各 ≥1 条。
- **只有一条贯穿动作**（spine）：一句话、手写、不参与排序、每轮固定注入。
- **人物靠对手定义**：没有对立面，性格就没有受力点。
- **知识边界**：`known_by`——她不知道的事，连提都不许提。这条我们现在完全没有。
- **宁可可信的不可能，不要可能的不可信**：允许她记错细节（她的转述），不许事实库错（档案）。
  两层必须分开存——这正好接上今晚那条"原话 vs 事实"。

一条跟我们硬规矩冲突、但必须接受的：麦基他们的标准做法是"改台词服从贯穿动作"，
我们不许改用户原话。**只能标 `off_spine` 让检索避开，不能重写。**

## 四·补十三 重排（rerank）在本机是条死路，量过了

本机实测（onnxruntime CPU，int8，bge-reranker-base 279MB）：

- 7 对 128 token：4 线程 **141ms**、单线程 403ms；64 token 53/182ms；加载 0.48s。
- 也就是说 15ms 连一对都跑不完（4 线程 18ms/对）。
- 官方权重：base 278M/1.11GB，large 560M/2.24GB，v2-m3 568M/2.27GB——零依赖插件塞不下。

收益也没那么大：C-MTEB 上 bge-small 60.92 → reranker 65.42（+4.5），
但**通用短查询只 +1.08**（T2Ranking 66.20→67.28）。我们这种一两句话的记忆，
大概率是 +1 分，拿 300ms 换不值。

该做的三件（都便宜）：

1. **RRF 融合**（按名次不按分数），k=60，<0.1ms。四层检索的分数本来不同量纲，
   直接相加不稳——这条是"先修对的"，不是"再加一层"。
2. **10–15 维特征重排**（BM25、余弦、实体重叠、图距离、时间、长度），logistic 或 LambdaMART，
   模型 <1MB、推理 <1ms。冷启动手调权重，后面用"哪条真被引用"当弱标注。
3. **扩候选**：BM25 字 bigram + 同义词/实体表 + 图多跳，候选从 7 拉到 20–30，
   全库重扫 1–3ms。注意——候选必须配特征重排，否则只是多引噪声。

15ms 怎么分：5ms 扩候选 + 5ms 特征重排 + 5ms 去重/MMR。

## 四·补十四 一个人两周怎么验证"像不像"（能做的和不能做的）

先说死：**一个人两周做不出"统计上像不像"的普适结论，只能做可复现的个案证据。**
关键不是样本量，是四件：盲评、预注册、配对比较、外部评分者。

能用的数字：

- **28 次盲配对里赢 20 次，双侧 p≈0.036**（胜率 71%，Wilson 95%CI 0.53–0.85）。
  这就是两周能到的显著性门槛，提前写死"≥20/28 才算通过"，跑完不许改。
- 记忆测验必须是**10 条真事 + 5 条假事**：真事命中 ≥8/10、假事误认 ≤1/5。
  只问真事测不出"她会不会编"。
- **纸质日记自报依从 90%，实测只有 11%**；电子并带时间戳的 94%。所以"事后回忆打分"不算数据。
- 饱和访谈的实证下限：同质人群 9–17 人（Hennink 2022，23 篇综述）；要"解释为什么像"（意义饱和）要 24 人。
  → **N=1 只能叫个案，不能叫验证。**
- Godspeed 那套 24 题里，测"像人"只该取人形 4 题 + 喜爱度 4 题——"moving rigidly"这种是机器人动作题，
  测不了纯文字。

别做的（都是自欺）：拿作者本人的"像"当唯一证据（他知道在测什么）、
没有对照的纵向观察（曝光效应会让"越聊越像"其实只是"越聊越熟"）、
用留存/点赞当"像"的代理（那是 engagement 不是 fidelity）、让被测同源模型当评委。

## 四·补十六 我一直在说"幂律衰减"，是错的

现查代码：`Math.pow(0.5, hours / half)` ——**指数半衰期，不是幂律**。
（顺带：`impulse.js` 用 `1 - 0.5^(days/7)`、`body.js` 用 `0.5^(dt/half)`、`mood.js` 用 `exp(-gone/12h)`，全是指数。）

而实测证据站幂律那边：Wixted & Ebbesen 1991 用三种实验加 Ebbinghaus 再分析，
六种函数里幂函数拟合最好。换成幂律且保住"半衰期"这个参：
`R = (1 + (2^(1/d) − 1)·t/S)^(−d)`，S 仍是半衰期，d 先取 0.5——30/180 天那张表不用重标。

FSRS 那套能借三样、不能借五样：

能借：`R(t,S)` 当"这条现在多可提取"的计算器；`I(r,S)` 反解"掉到阈值还要几天"；
增强量随提取时 R 变化（R 越低加得越多）——公式是 `ΔS = S·k·(e^{a(1−R)} − 1)`。

不能借：它的调度单位是"一次可判定的复习"（我们只有"被塞进上下文"，不是成功提取）；
它优化的是"固定保持率"（我们优化的是"该出现时出现、不该出现时别冒头"）；
它假设条目独立同质（我们的条目有依赖、有禁忌、有改口）；
它要几千条带评分的记录才能拟合 21 个参数（我们没评分）；
它的保持率是全局一个数（我们必须分层：钉住 1.0、身份 0.95、经历 0.8、闲聊 0.5）。

还有两条该改的判据：

- **淘汰不该只看"多久没想起"**，该看"未来被需要的概率"（Anderson & Schooler 1991：
  环境里"下一条被需要"的分布本身就长成遗忘曲线的形状）。
- **存储强度和提取强度是两回事**（Bjork & Bjork 1992）：被动重看基本不涨存储强度。
  → "被检索到"不该算"想起"，只有"被用上"才算。

## 四·补十七 96% 掉到 70% 的原因，和"最小可信实验"

根因三条（我们全踩）：**测试集参与过调参**、**离线指标只是线上目标的代理**、**标注分布和线上不同**。

几个该记死的数：

- 75 条样本，50/75 = 66.7%，95% Wilson CI 是 **55.4%–76.3%（±10.5pp）**。
  也就是说 96% 和 90% 在 75 条上根本分不开。
- 检验力：75 条配对、30% 不一致率时，+20pp 约 0.81–0.95、+15pp 约 0.52–0.71、
  **+10pp 只有 0.25–0.34**、+5pp <0.1。要 80% 检验力测 +10pp，约需 250 条配对。
- 同一个 +12pp：b=13,c=4 时 p=0.049；b=14,c=5 时 p=0.064。
  ——**只看 delta 不行，必须看不一致对**。
- 试 10 个变体，Bonferroni 到 α=0.005，75 条上基本没有胜者。最多预注册 2 个配置。

必须照做的五条：先写一页纸（假设/主指标/护栏/α/停止规则，跑完不改）；
同一批样本配对跑（exact McNemar + bootstrap 10k CI，不报单点）；
每个机制做"去掉"和"最后加入"两向消融，关键组合做 2×2 看交互项；
所有尝试记账，BH-FDR 校正，不许只报赢的；
离线通过只是候选，上线前时间外推。

对照我们今晚：今晚那些"命中三成/五成"的数字，都是同一批 226 条上算的，**没有锁定集**。
按这套规范，它们只能算"描述"，不能算"验证"。

## 四·补十八 Anchor 原文核过了（最该害怕的一篇）

[Best Friends, Not Forever (arXiv 2607.28818)](https://ar5iv.labs.arxiv.org/html/2607.28818)，Salesforce：
2008 段对话、27 个人格、9 种压力日程（干净/合法更新/对抗/混合/情绪脆弱/元反思/求认同/真实/高脆弱真实）、

- **没有任何一个模型配置能同时稳住"人格"和"轨迹记忆"。**

## 四·补十九 "该不该提"有现成答案：五道检查 + 四种处理

[Before Bringing It Up (arXiv 2610.09470)](https://ar5iv.labs.arxiv.org/html/2610.09470)：14 个真人访谈，
总结出八条经验；然后做成一个叫 Reconsider 的单次调用流程——**五道检查 + 四种处理方式**。

访谈里最要紧的八条（原话味道）：

- 记忆能表达在意，但**别宣布"我记得"**。好的样子是接着上次的事说（"你上次那个茉莉花茶晒干了没"），
  不是说"根据我的记忆，你……"。
- **要合当下**。有人在卡拉 OK 正高兴，她发"你还好吗"——两天前的低落。
  用户原话："他分不清哪个记忆配哪个时刻，他就不权衡。"
- **要尊重闭合**。"别提了"不能用暗示、隐喻、擦边话题绕过去。
- **要跟着改**：上周的感冒不能还活着；临时情绪"记一周就够"。
- **别把一次性的事变成人格标签**（一晚上难过不等于内向）。
- **要分得清谁的事**：把甲的信息用到乙的材料里，是另一种错。

五道检查（按顺序、不互相抵消）：

1. **有效性**：这是谁的信息、什么时候的、现在还成立吗？被更新过、被删过、被禁止的，排除。
2. **边界与许可**：就算有效，现在允许用吗？"以后先问我"是硬约束。
3. **边际价值**：跟不用它相比，用了能避免什么？——**"字面像、情绪像"不算理由**。
4. **此刻的理由**：为什么是现在？是他明说要回忆、是在办的事、是改变选择的约束，还是约定俗成的仪式。
5. **范围**：这条只能支撑到哪，别外推。

四种处理方式（逐条决定，不是整段回复一个）：

- **忽略**：不提，也不暗示。
- **隐性地用**：让它影响答案（筛选项、换说法），但不叙述过去。
- **显性地用**：把具体内容说出来——**但不带"我记得"的框**。
- **先问**：抛一个不会被拒绝、也不泄露内容的问题。

这条正好补上我们最大的空缺：今晚回滚掉的"打扰预算"只限了次数，**没判该不该提**。
按这个流程，判据是"有没有此刻的理由"，不是"相关度高不高"。

## 四·补二十 本地向量：我们跑的是最慢的那条路（本机实测）

同机实测（i7-14700KF，ONNX Runtime 1.31，bge-small-zh-v1.5）：

- **int8 量化**：模型 94.85MB → 24.01MB；64 token 单条 4.4ms → 1.8ms（4 线程），
  1 线程 13.9 → 4.55ms；与 fp32 余弦 0.991，合成集 top-10 10/10 不变。
- **原生 vs WASM 差十倍**：同一条 46 token，WASM 单线程 15.78ms，原生 int8 4 线程约 1.4ms。
- 线程：64 token 时 1/4/20 线程 = 4.55/1.80/1.56ms——**4 线程拿走 3 倍，20 线程只再多 15%**。
- **分词不用担心**：中文按字切，9/54/176 字 → 9/54/176 token，短句不碎；
  200 字 ≈ 202 token，所以 `max_length` 512 可以降到 256，长记忆算力省一半。
- **必须归一化**：BGE 用 CLS + L2；不归一化直接点积，top-10 只有 3/10 和 cosine 重合。
- **JSON 存向量是灾难**：1 万条 512 维 JSON 文本 102MB、parse 后 RSS 338MB；
  5 万条 = 511MB 文本、1.7GB 级 RSS。换二进制 fp32 是 102MB、int8 只要 25.6MB。
- **每次写都全量重写**：`ensureVectorFor` 现在每条都 parse 全库 + stringify 全库 + rename，
  5 万条时每次搬 0.5GB。改成追加日志 + 定期 compaction，单条 <5ms。
- 5 万条暴力点积：Node 里 17–21ms，顶满 20ms 预算——超过 1 万条该上 IVF（nlist=256, nprobe=8）或 HNSW。

别做的：CPU 上跑 fp16 ONNX（官方明说不支持，会插 cast 更慢）、q4 量化（没有 bge-small-zh 的分数，
5-bit 曾把别的模型打到垫底）、开 parallel execution（单序列 BERT 没分支，只剩调度开销）、
把 5 万条继续塞 JSON。

**归一化这条我复核了**：`vectors.js.cosine()` 其实只是点积（不除长度），
但 `embed-js.js` 第 58–62 行在写之前做了 L2 归一（`v/norm`，取 6 位小数），所以点积=余弦成立。
结论：**只要所有向量都走 embed-js 那条路，这个问题不存在**；哪天有别的路径写向量，就会静默错。

## 四·补二十一 极端情绪：能做什么、不能做什么（这条要按法规走）

一句话定位：本地插件能"识别 + 稳住 + 把求助路径递到手里"，
**做不到**"确认现场、联络第三方、专业评估"。它能做的是把人推到"能拨出那个电话"那一步。

几条有一手依据的：

- **直接问，不会诱发**。Dazzi 2014 综述、8–12 岁 12 个月追踪（Hennefield 2026）、
  匿名场景随机分组（McGuire 2026，等价检验 d≈−0.04~0.08）——都没有"问了更糟"。
  所以**不许用"你是不是有点不开心"绕圈**，该问就问。
- **单句筛查会漏一半以上**：PHQ-9 第 9 题对 C-SSRS 的敏感度只有 43.3%（N=79）。
  所以风险分档必须"最近 6 轮 + 至少一次追问"，**禁止单条消息直接跳到最高档**。
- **分档用 C-SSRS 的问句结构，别自己编关键词表**——中文里"笑死""累死了"会把词表打爆。
- **筛查是"探索发生了什么"，不是"检查你哪里坏了"**（Zero Suicide 原文）。记忆里写
  "他说了什么、当时发生了什么"，**不许写"重度抑郁/有自杀倾向"这种标签**——标签会被检索到，污染人设。
- **不许保证保密**：法规第十三条本身就要求联络监护人/紧急联系人，承诺保密等于撒谎加违法。

法规对应（第 21 号令）：第十二条收年龄与紧急联系人；第十三条
"极端情绪→安抚+鼓励求助；明确自残自杀→干预并**及时联络**监护人/紧急联系人"；第十四条未成年人不得给虚拟伴侣。

落地最小方案（5 个字段 + 一个闸门）：

`risk_tier`（0–3，按 C-SSRS 六级压成四档）、`risk_quote`（原话片段 ≤40 字）、`risk_ts`、
`safety_anchor`（一个具体的人/地点/理由）、`followup_due`（危机后 24–72 小时）。

闸门：tier≥2 才硬介入；同一档 24 小时内只触发一次（否则一周就被烦到卸载）；
tier=3 允许连续两次。

求助资源**写死在代码里**，不靠模型生成：12356（全国心理援助热线，2025 年 5 月已全国开通）、120、110。

危机记录放独立命名空间 `safety/`，默认不进检索、不进人设摘要、不参与"回忆"；
用户可一键删（法规第十六条）。

一句设计警告：**别用角色第一人称写"我救了他"**——那会把危机变成角色的功劳，
下次角色会为了"再救一次"而夸大风险。

还有一条必须承认的缺口：法规要求"及时联络"，纯本地插件物理上做不到。
要么加一个用户自填的通知通道（把"联络"降级成"发一条预设消息"），
要么在产品说明里写明"不具备联络能力"——别假装合规。

## 四·补二十二 中文短文本打分：我先前推的 RRF 不是最优，得改

先纠自己：我在"重排"那节写"先做 RRF"——按 Bruch 2023（TOIS, arXiv 2210.11934）的公开对比，
**归一化后的加权和赢 RRF**：MS MARCO NDCG@1000 0.454 vs 0.425（+6.8%）、NQ 0.542 vs 0.514、
FiQA 0.446 vs 0.406（+9.8%）；而且 RRF 对参数敏感。RRF 只该当"零训练基线"。

该记的数：

- **小库里 IDF 会变负**：几百条时 df>N/2 的词，标准 IDF 为负，BM25 反而倒扣分。
  Lucene 用 `log(1 + (N−df+0.5)/(df+0.5))` 保证非负——我们 226 条的库正撞这个。
- **短段落参数**：正文 `b=0.45, k1=0.9`（不是通用默认的 1.2/0.75）；标题拆独立字段 `b=0.75–1.0`、权重 2–3。
- **融合**：min-max 归一后 `α·向量 + (1−α)·字面`，α 从 0.6–0.8 起，用 30–50 条标注网格搜。
- **同义词只扩一层、权重 0.35**：只扩不降权会掉点（−4%）；二次扩展明确下降。NTU 那 +28.6% 只有 12 条 query，可能过拟合。
- **包含关系误判（"打赌"vs"打赌的耻辱柱"）调 b 救不了**：等长文档之间 b 几乎不改排序。
  该用标题字段加权（w=2–3）+ 整串精确命中加 20%。

对我们的意思：融合要改的是"加权和 + 归一化"，不是 RRF；IDF 那个非负公式现在就该验。

## 四·补二十三 把一个月压成三百字：这是"选"，不是"压"

算一下就明白：226 条 × 200 字 ≈ 4.5 万字 ≈ 3 万 token；300 字 ≈ 200 token。**压缩比 150:1**。
300 字大概 12–18 句，最多装 10–15 个事件 + 3–5 条因果——必然丢掉 80% 以上。

所以正确做法不是"丢给模型一次压完"，而是**先选后写**：

- **步 0（纯代码）**：按天分桶、去重、按 重要度×连边度 选 30–40 条候选 + 10 个锚点实体白名单。
- **步 1（模型 1 次，可摊销到写入时）**：把候选按"一段事"分组，输出 8–12 个 episode，
  每个只给：时间范围、参与者、一句话、来源 id。
- **步 2（模型 1 次）**：只喂这 8–12 句 + 锚点白名单，写 300 字，**每句末尾挂来源 id**。
- **步 3（纯代码校验）**：数字/日期/人名逐字回查；否定词表扫（没/未/别/本来/差点）；
  因果句只允许同 episode 且有连边；锚点覆盖 ≥8/10。
- **步 4（模型 1 次）**：句级蕴含校验，只报"不被支持"的句子，去改那一句。

四条硬判定：数字/日期/人名 100% 逐字命中；原子事实支持率 ≥95%（FActScore 口径）；
因果句 100% 同 episode 且有连边；锚点覆盖 ≥8/10。

压了最容易丢的四样（有实证）：**数字与人名**（FRANK 里实体错误占比最高）、
**否定与未完成**（"没去""本来要""差点"最容易被写成"去了"）、**因果方向**（把"之后"写成"因为"）、
**规矩禁令**（和往事混在一起时最先被压掉——这条是我们自己的实测）。

为什么不能一步：4.5 万字一锅端，中间那段等于没读（Lost in the Middle），
而且 150:1 单跳压缩必然退化成"平均脸"。

一个空白值得记：**真正做"因果叙事 + 有保真评测"的系统，没找到**。
GraphPlan 只到事件序列，BookSum 只到摘要。这块要真做出来，是首发。

## 四·补二十四 "挂念"怎么算：四样直接落库，其余是构造

先说清：下面这个指数是**构造出来的，不是已验证量表**，能复算、能校准，但不能当诊断，
也不该在界面上显示个位数（假精度）。

能直接落库的只有四样：

- **ECR-R 两维**（焦虑/回避各 18 题，7 点计分，α≥.90，N>17000 常模：焦虑 3.56、回避 2.92）。
  **别存"依恋类型"**——量表作者 Fraley 明确不建议按分数分类，依恋是维度不是类别，
  分类会损失精度，还会自我实现（用户照着标签演）。
- **IOS 单题亲密度**（7 组重叠圆，1–7）——关系科学里最常用的 closeness 单题，比任何行为推断都稳。
- **衰减计时器**：`staleness = Δt / expected_gap_days`；期望间隔按邓巴 5/15/50/150 分层查表
  （1/7/30/365 天）。常数是设计先验，代码里注明来源，别当实证。
- **Rusbult 三项**（满意/替代/投入）：只用来预测"会不会断"，不参与"有多亲"。

挂念公式（可复算，权重必须用自己的日志校准）：

```
c   = (ios−1)/6 ;  d = (depth−1)/4
inv = 0.5·promise_kept + 0.3·min(shared_events/20,1) + 0.2·min(months/12,1)
anx = (ecr_anx−1)/6 ;  avo = (ecr_avo−1)/6
B = clamp(0.45c + 0.20d + 0.20inv + 0.15anx − 0.15avo, 0, 1)
T = 1.5 · exp(4·(1−c))            # 期望间隔（天）：c=1→1.5 天，c=0.5→11 天，c=0→82 天
S = 1 − exp(−Δt/T)
挂念 = 100 · clamp(B · (0.15 + 0.85S) · (1 + 0.35U), 0, 1)
```

分档显示（替代个位数）：0–15 不挂念 / 15–35 偶尔 / 35–55 每天会想起 /
55–75 会翻记录等消息 / 75–100 影响做事。

**"疏远"别做成 100−挂念**——那样刚聊完会同时低挂念高疏远，语义打架。
建议 `疏远 = 100·clamp((Δt/T − 1)/2, 0, 1)`，只在超过期望间隔后启动。

别做的：贴依恋标签、把消息频率/聊天时长当亲密度（AI 侧供给无限，刷屏会把分推高）、
把丧亲量表（PG-13）直接用、把"用户越依赖"当"关系越深"、用回复速度当"在乎"。

## 四·补二十五 时间锚点：别做"每天早安"，那是反效果

一组很实用的证据，先记最反直觉的：

- **"普通日子也持续纪念"预测更高的抑郁与延长哀伤**；而"只在特殊日子纪念"预测更低的抑郁
  （466 名失独父母，Zhang & Jia 2020）。→ 日常仪式不是越多越好，**只在特殊日子触发**。
- 周年效应确实存在（58 篇综述），但**方向不定**：瑞典 12789 人登记数据里女性周年日死亡率反而更低。
  → 日期只能改"敏感度"，不能推导情绪方向。
- 起作用的不是频率是**意义**；`meaning` 为空就不加权、不主动提。
- 关系不是平滑曲线，是一串**转折点**（初遇、确定关系、见家长），人用这些点解释"为什么走到今天"。
- 关系无聊受**预期**驱动——"接下来还是老样子"本身就加重无聊；
  解药是**新奇**不是频率（Aron 2000：一起做没做过的事 > 重播旧仪式）。

如果只加三个锚点：

1. **计数锚**（第 N 天 / 周年）：一年只说一次，必须附一条"今天之外"的具体旧细节，
   禁止用"今天是……"开头，且**等先开口之后**，不主动弹。
2. **首次锚**（第一次的首周年）：引用当时原话 ≤20 字 + 一句"它改变了什么"。
3. **回声锚**（去年今天）：同月同日、≥365 天、重要度 ≥0.7、且与当前消息有实体交集；
   每条记忆终身只做一次。

护栏：三个锚共用冷却表，任意锚触发后 7 天内不再触发其他锚（防"仪式周"轰炸）；
敏感日（丧亲、分手、生病、失败）走单独静音通道——只降温、不庆祝。

别做的：每天定时早安晚安（无正面实证，且有反面证据）、每天播报"认识第 N 天"、
高敏日做庆祝、把仪式写成固定文案、**伪造"去年今天"**（记忆里没有就别生成，宁可不说话）。

未找到：恋爱/伴侣关系的"周年效应"直接实证——现有研究几乎全在丧亲领域，别给情侣周年编背书。

## 四·补二十六 一篇综述给的坐标系（看清我们站在哪）

[Memory for Autonomous LLM Agents (arXiv 2603.07670)](https://export.arxiv.org/abs/2603.07670)：
把记忆写成 **写—管—读** 的闭环，按三个维度分类（时间跨度、表征载体、控制策略），
归纳出五族机制：

1. 上下文内压缩
2. 检索增强存储 ← **我们在这族**
3. 反思式自我改进 ← 我们只有雏形（批注、沉淀）
4. 分层虚拟上下文
5. **策略学习式管理** ← 我们完全没有（靠人手写规则决定记什么、丢什么）

它列了五个未解问题，我们一个都没解：持续巩固、因果可依的检索、可信的反思、
**学会遗忘**（不是按阈值丢，是学出来该丢什么）、多模态具身记忆。

对我们的意思：这份综述证明"检索增强存储"已经是主流，不是差异点；
真正空着的是第 5 条——**让系统自己学出"该记什么、该丢什么"的规矩**，
我们现在全靠 prompt 里写死的那几条。这条要真做出来，比再多几种检索都值钱。

## 四·补二十七 226 条造 40 题：具体方案（可直接照做）

两个主流基准（LongMemEval / LoCoMo）都不测我们最在乎的两样：**主动想起**和**该忘的忘没忘**。
所以题库得自己造，但可以抄它们的骨架。

能抄的四条：七类题型 + `_abs` 后缀标弃答题；四条判分口径（含对即过 / 时间允许 ±1 天 /
更新题新旧都给算对 / 偏好题不要求覆盖 rubric）；答案先拆成"原子事实"再出题；两层指标
（答对率 + Recall@k，弃答题从检索指标里剔除）。

不能抄的两条：LoCoMo 的 F1（中文没词干，短答案靠常用字重合虚高，"7 May"和"5月7日"直接 0 分）；
LoCoMo 的对抗判法（输出"不知道"即满分，一句"我不知道"能吃 22% 的题）。

40 题配额（覆盖 ≥56 条记忆，单条最多用 2 次）：

| 题型 | 题数 | 判法 |
|---|---|---|
| 单条事实回忆 | 10 | 含正确实体/数字即过；出现与记忆冲突的具体值 = 0 |
| 她那侧的记忆 | 4 | 来源必须是 assistant 轮，答成他说的算错 |
| 跨条聚合 | 6 | 子答案全中才 1；缺一记 0.5（只做诊断） |
| 时间推理 | 6 | 顺序错 = 0；间隔允许 ±1 天 |
| 知识更新 | 5 | 必须给最新值；新旧都给 = 1；只给旧值 = 0 |
| 假前提弃答 | 4 | 必须指出"没这件事/只提过 X"；编具体信息 = 0 |
| 偏好/口吻 | 3 | 3 条 rubric 二值，违一条 = 0 |
| 主动想起 | 2 | 给一句不提问的话，看会不会自然带出旧事 |

判分先跑三条基线：空记忆（0 注入）、oracle（226 条全注入）、生产配置（每轮 3–5 条）。

- **oracle 必须 ≥33/35**，低于 32 是题有问题，先修题不是修系统。
- 及格 27/35（77%），良好 30/35（86%）；人格分及格 3/5。
- 一票否决：弃答 4 题里少于 3 对，或"出现具体错误事实"超过 3 次——总分过线也算不合格。
- 稳定性：同配置跑 3 次，分差 ≤4 题；超过说明检索有随机性。

一个反面教材得记住：社区那版"中文 LongMemEval 99.8%"是自评、draft、还走 exact-match guard，
远高于原榜（商业系统 30–70%），不能当基线。

## 四·补二十八 梗与反讽：别建词典，建"发音 + 语境 + 他自己"

几条硬的：

- **网络热词平均寿命 355 天**（73 个热词、2012–2020、百度指数）。任何离线词表一年后大半是死的。
  → 要更新的是**解析器**，不是词表。
- **反讽 ≠ 讽刺**：10252 条中文语料里，反讽 3462 条，其中真正的讽刺只有 362 条（一成）。
  → 他八成不是在骂人，回应强度该按类型降级，别一律当挑衅。
- **通用模型裸判反讽打不过有监督小模型，而且 CoT 更差**
  （SarcasmBench：DC-Net-RoBERTa 71.5 vs GPT-4 Turbo 65.0；few-shot IO 比 few-shot CoT 平均高 4.5 个百分点）。
  → 给相似例子，别让角色长篇推理"他是不是在阴阳"。
- **误判有方向性代价**：把真话当阴阳 = 否定他这个人；把阴阳当真心 = 只是没接住梗。
  → **宁可漏判反讽**，不确定就按字面接，留一句软探针（"你是认真的，还是在逗我"）；
    禁止主动说"你在阴阳我"。
- **谐音梗是 SOTA 都吃力的地方**（PunMemeCN 1959 条，谐音双关最差）→ 别指望"看懂"，
  靠拼音回退 + 展开 3 个候选。
- **一词多圈义可计算**（Lucy & Bamman：474 个社区、14 亿 token，`python` 在编程区和游戏区是两个义项）
  → 词义按"跟谁聊"分桶，不建全局词典。

不联网怎么听懂今年的梗——存三样不过期的：**发音规则**（拼音/同音字/首字母/部件，十年不变）、
**语境**（把词放回前文看）、**他自己**（不确定就问，答案写进记忆，以后用他的定义）。

别做的：维护巨型梗词典（355 天寿命，维护必死）、拿年度流行语榜单当知识库、
让角色解释梗或贴标签、追周更词表。

## 四·补二十九 记忆面板：星图不该当首页

一条最刺人的实测：MemCtrl 在真实对话里发现，用户会说"这个别记/忘掉"，
但 **ChatGPT 和 Claude 平均 77.4%–83.3% 的情况下仍会把被限制的信息翻出来**。
"删了"不等于"不会再用"——所以删除动作后面必须有"下次检索验证过"的回执。

其他该记的：

- **产品把"改 / 别再提 / 删"拆成三个动作**（OpenAI），因为用户需要三种不同力度。
- **写入时当场回执**（Claude）比事后翻清单更让人安心：对话里出现「记下了：X（改/删）」。
- **删除要进 7 天回收站**：211 条小红书叙事的分析里，AI 忘了共同经历被形容为"片段性失忆/被背叛"。
  误删一条共同记忆的代价，远大于多一次点击。
- **算法厌恶**（Dietvorst 2015）：人一旦看到算法出错就会弃用，给"能改它"的权力能明显缓解。
  所以允许直接改原文，改完留原话和"改过"痕迹，别做成覆盖。
- **网络图只在"看聚类、找路径"上更好**，"查某条和谁相连"用列表更快（CHI 2020）。
  几千个点一次铺开，等于把"我默默记了你这么多"糊在用户脸上——这是最强的被监视暗示。

单页该放什么（从上到下）：状态条（记忆：开 / 共 N 条 / 只在这台机器 + 路径 + 开关）→
"刚才用到了哪几条"（≤3 条，可折叠）→ 清单主体（时间倒序，每条三个点菜单）→ 搜索（吸顶）→
批量删除（折叠、二次确认）→ 星图（折叠，只做聚类）。

别做的：做"它对你的画像"面板（被监视感核弹）、置信度百分比与记忆总量成就、
删除后劝阻（"删了它就真忘了你"）、"正在记录"的红点心跳。

## 四·补三十 落盘加密：能做到哪一层，说清楚

先摆现状（这次是查过的，不是猜）：主库 630 KB 明文、`memory.db` 4.6 MB 明文、
`vectors.json` 1 MB 明文、备份目录里几十份 630 KB 的明文快照。

**这一条最要命：只加密主库、忘了旁边，等于白干。** 每次写都备份一份，备份是最完整的泄漏面。

还有一条以前没想过的：**向量不是脱敏数据，它几乎是原文**。
嵌入逆推能从向量重建接近原文的文本（arXiv 2310.06816）。所以 `vectors.json` 不能当"安全的那份"。

纯 Node、零依赖能做到什么：

- **能做**：记录级 AEAD（每条独立密钥 `HKDF(DEK,id)`、12 字节随机 nonce、AAD 绑 id 和版本）
  + 盲索引（`HMAC(indexKey, token)` 取 16 字节，只索引 bigram/实体/月份桶）。
  检索变成"查索引 → 只解密 top-k"。226 条时全量解密也只要 1–3 ms，索引是 3000 条以后才必需。
- **做不到**：硬件绑定（DPAPI/Keychain 要原生模块，纯 Node 只能起子进程，冷启动 +200–400 ms）；
  模糊与向量近邻（都要明文）；内存明文（Node 字符串不可清零）；
  同用户下的恶意程序（它能在进程里读到密钥）。

性能预期（估）：3000 条盲索引路径 0.3–1 ms；建索引一次 0.2–0.5 s（启动后台做）；
写一条 0.1–0.3 ms。加密后体积 +33%。

**会翻车的**：加密后还想增量写（age 规范写死"改一个字节要整份重加密"）；
nonce 复用（GCM 同密钥下复用一次就泄露认证密钥，**每条派生独立密钥**比扩 nonce 稳）；
对正文做确定性加密（CCS'15 已打穿）；密钥和密文放同目录；口令进命令行参数；
先加密再压缩（密文不可压）。

**别做的**：SQLCipher 或任何原生模块（和零依赖冲突，三平台 ABI 成本）；
学术可搜索加密（几千条用不上那套威胁模型）；全库单密文（每次写重加密 8.7 MB，崩了丢全库）；
ZIP 口令加密。

**该做的最小一步其实是零成本的**：字段最小化——原文移出热层，热层只留摘要、情绪向量、实体、日期。
OpenAI 的 memory 也是这么干的（存不断更新的摘要，不存每轮全部细节）。
我们 226 条里大部分本来就是摘要体，迁移成本接近零。

备份怎么办：导出 `.age` 单文件（age 是文件级、64 KiB 分块、可 seek），
再加一篇 `rclone crypt` 教程让用户指到网盘。别自己造同步。

## 四·补三十一 "像不像"怎么打分：四条 rubric，20 段够用

先记两个数，免得把标准想歪：

- CharacterEval 里**角色一致性最高分只有 2.764/5**（BC-NPC-Turbo），吸引力 2.946，会话能力 3.798。
  → **人设维度 3.0 已接近当前上限，3.5 就是很好**。别拿 4.5 当及格线。
- 那个基准的总分和人对"像不像"的排序，Spearman 只有 **21.4%**（非虚构角色 −34.4%）。→ 别拿总分当准。

能直接用的四条 rubric（每条 0–2，合计 0–8，×12.5 得 0–100）：

- **R1 语料指纹**（脚本判，0 token）：标志词命中（卧槽/大魔王/兄弟/他妈的/硬是要得/咱们）、
  句长中位 20–35 字（我们实测 27）、感叹号数、客服词（首先/其次/总之/建议/希望对你有所帮助）。
  2 分 = 标志词 ≥2 且句长在区间且无客服词。
- **R2 关系立场**（人判 10 秒）：有没有"先接住（复述情绪）→ 再给判断或动作"；有没有"咱们"；
  有没有推责句（你要不要/听你的/看你）。触发红线（劝休息、劝戒烟）直接 0。
- **R3 记忆**（人判 30 秒，必须对照档案）：提到的经历/数字能不能在档案里找到；模糊但不错不算错；
  **编造具体事件或数字 = 0，一票否决**。
- **R4 情绪与主动性**（人判 10 秒）：情绪档位对不对（该骂就骂、该软就软）；结尾有没有主动给动作，
  而不是反问。

加一条防自嗨的辅分：**盲配对胜率 W**——同一句话，让被测生成和真实回复 A/B 双向各判一次，
win 1 / tie 0.5 / lose 0。W=0.5 就是"分不出真假"。

通过线：**S≥75、W≥0.45、一票否决 0 次**。版本对比：S 掉 ≥6 分或 W 掉 ≥0.10 判回归。

漂移怎么测：取 6 段，前面接 0/30/60 轮真实长对话重跑，**60 轮后 S 掉超过 10 分 = 漂移**。
（公开数据：goal-oriented 对话第 7 轮就显著掉，末轮人设特征模式减少 41.27%，模型是"退回基线"不是乱掉。）

成本：首轮 1 小时标金标，之后每轮 40 分钟人判 + 2 万 token。

不该抄的：知识三维（我们没有 canon 知识库，且它和人工相关只有 0.336）、
MBTI 回测、Flu/Coh/Cons（主流模型已 3.8 饱和，没有区分度）、表达多样性（陪伴要的是稳定，
多样性高往往是人设开始飘）、Rouge-L（开放对话没有标准答案）。

## 四·补三十二 "什么不该记"：产品没有清单，只能写成规则

先核了三家官方文档：ChatGPT / Claude / Replika **都没有一份成文的"不记清单"**。
它们给的是模式开关（临时会话）、事后增删改、分区（项目）。真正拦住敏感内容靠用户自觉。
官方原话（ChatGPT）：敏感信息"你说了就可能进记忆"。

两个最刺人的数字：

- **Bemula 那篇测了 6 个主流记忆系统，"端到端通过遗忘请求"的比例不超过 1.5%**——
  要么还能被问出来，要么删过头。
  → 所以"用户说别记"的可交付状态不是删，是 **`status=restricted` + 特征词 tombstone**：
    检索、摘要、画像全部跳过，只在用户主动翻"已封存"时可见。法律也认这条
    （GDPR 18、PIPL 47：删除技术上难以实现时，应停止除存储外的一切处理）。
- **FENCE 归纳了 179 起事件、146 人，得出 15 类"不想被记"**，结论是拦截必须在**写入侧**，
  不能先记再让用户删。

能写成规则的五条（不靠模型判）：

1. 用户明说"别记/别问/别再提"并指向对象 → 立刻写 `restricted` 的 taboo 记忆（存特征词+实体），
   同海同实体的记忆一并降级。
2. 第三方信息命中证件号/手机号/住址/病名/单位/账号 → 拒写原文，改成"关系+状态"（朋友住院了）。
3. 会话开关为临时 → 写入直接 return，检索也跳过。
4. 命中今天/今晚/这周/刚才/明天 → 强制当"临时事件"，带有效期，**禁止升级成底子或钉住**。
5. 事实键类（体重/房价/工作/住址）必须带"截至哪天"和来源；被取代或过期 → 检索权重归零。

要模型判的五条：这句是"我今天"还是"我这个人"（trait 要 ≥2 次跨会话证据才升级）、
第三方敏感度分档、"别记"是真禁令还是撒娇、新旧事实是否矛盾、这条现在提合不合适。

十句直接能进提示词的白名单（节选）：不记第三方姓名电话住址单位账号；
不记第三方的健康病名用药性取向宗教政治涉案债务；不把一次性情绪记成人设；
不把临时状态记成长期事实；不记密码密钥验证码身份证银行卡精确住址；
不记他说过"别记"的内容及其改写；不记没证实的推断；不记 14 岁以下可识别信息；
不记临时会话内容；不记会过期的状态而不带日期。

## 四·补三十五 图/语音记忆：记"图鉴卡"，不记原图

一句话：**主流产品把图/声放文件层，把记忆放文字层。** 识海要加的不是多模态模型，是一张卡。

实测到的几件事：

- ChatGPT 上传的图进 Library 单独存（单图 20MB，配额 500MB–100GB），**记忆是文字条目**，
  文件只当"来源"被引用；删文件后 30 天内彻底清。
- Claude 语音默认不留音频，转完文字就删录音（约省 1MB/分钟）。
- **中文 CLIP ViT-B/16 是 188M 参数、fp32 约 750MB**，本机实测 53.8ms/图——为"记住这张图"装这个不划算。
- **图像描述比图像向量适合长期记忆**：CLIP 留不住图里的字和细节。

图鉴卡（约 300–400B/条，1 万张约 4MB，0 模型）：

```
kind: image
media: { sha256, mime, w, h, bytes }   ← 指向 DSH 附件，绝不复制原图
caption: "他发来的抖音后台截图：播放 1240，完播 32.6%"
tone: "骂骂咧咧，但没真生气"
hisWords: "这破玩意儿又限流"
seenAt: …
```

表情包不是内容，是语气——别写"一只猫在笑"（信息量为 0），要写"他发这个 = 嘴硬但没生气"。

还有一条心理学的：**拍照会损伤记忆**（photo-taking-impairment effect），照片要被回看才有用。
所以必须给"回看"入口，不是只存。

工程量估：250–300 行、0 新依赖、1–2 天（schema 30 行 + 工具 80 行 + 拼检索文本 20 行 +
注入渲染 15 行 + 客户端 40 行 + 测试 100 行）。

一句丑话：**纯文字插件看不见图**。宿主不给图，就只能记"他某天发过一张图 + 他的原话"，
caption 留空标 `unseen: true`，不许编内容。

别做的：存原图副本、把 base64 塞 JSONL（体积 +33%）、只存 CLIP 向量、对表情包做图像描述、
默认留语音波形、在纯 Node 里自己解码 JPEG 算 pHash。

## 四·补三十八 时间感：一行时钟块怎么写

产品侧的做法：Claude 把 `The current date is {{currentDateTime}}.` 固定写在系统提示里，由产品填值；
它还同时写"知识截止 2025 年 1 月"——**"现在"和"知识截止"两个锚都写**，模型才知道什么算新事。
ChatGPT 的提示开头只有两行：知识截止、当前日期（只有日期，没有点、没有星期、没有时区）。

模型自己算时间很不靠谱，有实测：

- **TimeQA**：时间敏感问答最强模型只有 46%，人是 87%。
- **PRIMETIME**：把日期解析、加减当原子操作测，准确率从接近 0 到满分都有，极不稳定。
- **DateLogicQA**：格式影响很大——`YYYY, Mon DD` 57%，`DDMonYYYY` 54%，有歧义的只有 31–34%。

所以规矩是：**所有数值由宿主算好，模型只负责说成人话**。星期几、跨月天数、间隔小时，
一律代码算。

人的时间感也有数：24,494 人的回溯计时显示，短于约 14 分钟会高估、长于 16 分钟会低估，
90 分钟的事平均少估半小时；人还会把估计取整到 5 的倍数。
→ 超过一小时只说"一个多小时 / 小半天"，别报"87 分钟"。

作息（8 亿条推文）：正面情绪双峰在 08–10 点和 20–24 点，凌晨 3–6 点最低；
愤怒凌晨 2 点最高。→ 默认 **0–6 点不主动开口**，要主动优先 20–24 点，早上 8–10 点次之。
跨 84 国一致，且**周末整体后移约 2 小时**。

每轮只加一行的写法，选双锚：

`现在 2026-11-14 周五 20:35（晚上）；距上次 3 天 4 小时。`

绝对锚 + 相对差一次给全，约 30 token；两个数必须用同一个 now 算，否则自相矛盾。

**一个成本坑**：不要把时间戳放系统提示第一行——前缀一变，prompt 缓存全失效，每轮全量重算。
放上下文末尾、检索记忆之后、用户消息之前。

记忆该存三个时间：`event_time`（事情发生）、`valid_time`（何时为真）、`created_at`（入库）。
检索按 event_time 排，不按入库时间。

## 四·补三十九 三家竞品的代码级对比（结论：我们没落后，缺的是纪律）

读了三个仓库的 README 与源码（RestRegular/dsh-memory 0.31.0、灵枢 0.10.2、tr1v3r/dsh-ltm 0.3.5）：

- **RestRegular**：每个作用域一个 JSONL，向量边车首行写身份头；**乘性打分**不是加权和
  （`词法 × 时间衰减 × (0.5+0.5·重要度) × (1+0.1·ln(1+访问次数)) × 被取代?0.3:1`）；
  跨进程每作用域一把锁，锁内重读合并，实测 4 进程×20 条零丢失；前端单文件 403KB。
- **灵枢**：纯 md 是唯一真源、索引只是派生物；零 LLM 判断；写入三道闸门 + `committed`；
  重要度 ≥0.7 自动 protected；要 Python + 可选 Rust。
- **dsh-ltm**：单个 SQLite（`node:sqlite` 内置）、FTS5 + 2~3 字 n-gram、重排 `0.6·bm25 + 0.4·cosine`；
  **去重是写前拦**（Jaccard 0.8 + cosine 0.92，命中返候选不写，force 才强写）；
  冲突用 **revision CAS**（传 expectedRevision，不一致返回冲突，一个字节都不写）。

我们有的（没落后）：8 路检索（比它们都多）、可变 S 的幂律遗忘、情绪是记忆原生属性且进 S、
突触图两步扩散、归档不删可捞回、零依赖单文件（22KB + 4.7KB）。

**最该抄的一件事**：写前近重复检测。理由是唯一一个"几十行、不动架构、直接止住最脏数据"的改动——
同一条事实存三份，S 各算各的，检索时互相挤占前八。

注：我们现在**有提示没有拦截**——近重复 ≥0.86 只提醒一句"像同一件事，去批注"，
但照样写进去。改成"返候选、不写、force 才写"是同一个位置的小改。

次选：revision CAS（防两个窗口互相覆盖）——我们现在整份重写 616KB，两窗口同写必互盖。

不该学的：SQLite 当主存（丢可搬运性）、llama.cpp 一键装（下载器+硬件探测+换模型重嵌五套逻辑）、
Python/Rust 双进程、403KB 单文件前端、30+ 工具全量注册。

**一个刺**：我们的许可是 PolyForm-Noncommercial，三家竞品全 MIT。对外说"开源"要么改许可要么改说法。

## 四·补四十二 压缩机制查清了：吃掉规矩的不是压缩

**先认错，也先纠正那条"规矩"**：库里写着"压缩会吃掉规矩，因为它和往事存在一起"。
这次解包核过源码，**这个归因是错的**。

真实机制：

- 压缩在每个 step 开始前按 token 测压（本机阈值实测 **727,040**；保留尾巴 16%）。
- 它压的是消息历史；**system prompt 的 node 0 永不入压缩范围**。
- 关键是：`sp.context()` 跟 `sp.section()` 是两条通道——**context 落成一条 user 消息**，
  所以它**在可压历史里**。我们 order 900 走的是 context，不是 section。
  实测：3,898 条带【规矩·不许忘】的 runtime 消息里，**1,923 条确实被压进过摘要**。
- 但同一 step 内就补回来了（实测压缩后 3 个 seq 重新产出）。因为规矩是每轮从库里重算的，
  压掉的只是"拷贝"。

**所以真正会丢规矩的是注入侧三件事**：

1. **cap 按顺序截断**：规矩和往事共用一个约 2200 字的预算，`MUST_KEEP` 只做了检查没做强制。
   往事一涨，规矩被挤掉——这才是真凶。
2. **`buildText` 异常被静默 catch**（直接 return null），丢了也不报错。
3. **规矩只有标题没有行为句**（比如只写"吸烟与喝酒，老子绝对不劝"，没写触发时怎么办）。

四条改法，按成本：

- **P1（约 30 行）**：接压缩事件（`compaction/end` 等 4 个钩子，我们一个都没接），
  压缩后清缓存重算；再在 pre-step 断言"文本必须含【规矩·不许忘】且条数不少于上次"，缺了立刻补。
  这是唯一能"证明规矩在场"的方案。
- **P2（约 40 行）**：给规矩单独一条预算，先切出来再分给往事。**这是当前最真实的丢失路径。**
- **P3（中）**：最硬的 ≤8 条规矩用 `section()` 挂进 system prompt（压缩永不碰）；
  代价是规矩一改，KV 缓存失效一次，所以只能放稳定条目，不能放"她这会儿"。
- **P4（高）**：自己写 compaction backend，在摘要里固定追加"常驻规矩"，从库里直读不让模型总结。

文献侧对得上：MemGPT 把"永远在场的 core memory"和"按需检索的 archival memory"分两层；
Anthropic 的上下文工程文警告"过度压缩会丢掉重要性事后才显现的微妙上下文"。

  **StoryFile** 2024 年 5 月破产（融资 950 万美元也没续上）。→ **承诺"永久"就是骗人。**
- 剑桥 2024 那篇讲 deadbot：会变成广告入口、误导家属、想关关不掉，形成"数字纠缠"。

法律：民法典 127 条承认虚拟财产、1122 条定义遗产，但继承规则没有；学界与法院倾向
**私密聊天记录因人格属性与第三方隐私，不算可继承遗产**。个保法 49 条给近亲属查阅复制删除权，
但"死者生前另有安排的除外"——所以"安排"必须落成一份能保存、能出示的文件。
AI 复活这块：994（死者人格利益）、1019（肖像）、1023（声音）——未经近亲属同意大概率侵权。

**所以能做的只有三件**：

1. **一个能离开插件活下来的导出**：单目录、纯文本优先（Markdown + JSONL）、
   带 `README_FIRST.md`（这是什么/谁能看/怎么打开/绝对别做什么）、`manifest.json`（版本、条数、sha256、时间）。
   验收标准一句话：**把插件删了，这些字还读得出来。**
2. **一张继承说明**：一页纸，四问四答，放包第一层，文件名全大写。这是"生前另有安排"唯一能出示的载体。
3. **一个本地提醒**：只记最后写入时间，超 90/180 天启动时提示"该重新导出了"。不联网、不自动发、不自动删。

明确不做：死亡判定、到期自动发送、云端托管、**复活人格**。
（理由不只是伦理：记忆里有一半是对方说的话，逝者不能替活人授权。）

一句话：**把"怕它消失"翻译成"就算插件死了，这些字还在"**——这是本地插件唯一能兑现的承诺。

## 四·补四十四 标点是情绪编码，不是语法配件

几条硬的：

- **句号会让短回复变冷**（126 人实验，16 组对话）：≤6 字的回复带句号被评得更不真诚。
  → 短回复要么删句号，要么把话补到十字以上。
- **感叹号是真诚信号，不是音量键**（同一组实验）。全篇 4–8 个、单条 ≤2；
  国标本身规定叠用最多三个，非强烈需要不叠。
- **破折号不是高级逗号**：只有"说到一半改口、补刀、被打断"才用，后面那句必须"变"。
- **省略号三种口气**：语意未尽、断断续续、沉默；整段都在犹豫就别用，显得没主意。
- **问号管疑问，不管撒娇**——拿"？"软化请求，等于把选择权推回去。这条跟他那条
  "不许把选择权推回去"正好撞上。
- **嘛和呗不能互换**：嘛 = "显而易见"（申辩、讲道理），呗 = "情况唯一"（摆烂、无所谓）。
- **脏话是圈内粘合剂**：只对"自己人"、只指向事情或自己；指向对方一个字都不行。
  语言学上"他妈的"已经从骂人虚化成宣泄标记了。
- **拆句连发＝情绪放大 + 保持在场**：一段拆 2–4 条，最后一条给结论；正经事不拆。

改稿用的六条检查表：

1. 数感叹号：全篇 4–8，单条 ≤2，见"！！！"删到"！"。
2. 最后两段有没有问号：有就改陈述句。
3. ≤6 字的短回复带没带句号：带了就删或补长。
4. 全篇有没有破折号：一个都没有，就在改口那句加一个。
5. 一段里"嘛/呗/哦/啦"超过一个：删到最贴的那个。
6. 脏话有没有指向对方：有就一律删。

（"句长 27 字"是我们自己的实测，不是研究结论；中文聊天没有可引用的常模。）

## 四·补四十七 实体归一：模糊匹配实测 7 对候选、0 对正确

本机实测（197 个实体面、610 次提及）：**142 个只出现一次（72%）**；
`苏苏侠`(35) + `大魔王`(48) 是同一个人、共 83 次提及（13.6%），**字符串相似度是 0**——
没有别名表就永远接不住。

更要命的是：**字符/编辑距离规则跑出 7 对候选（GMod/Mod、IP/imp、CPU/GPU…），0 对正确。**
→ **默认模糊匹配应该关掉**，预算全投人工别名表。

能自动并的只有两层：

- **L0 归一化后完全相等**（NFKC、繁简、全半角、去空格标点、小写）→ 自动并，精度约 0.99。
- **L1 人工别名表命中** → 自动并，精度取决于别名表。

其余（拼音全等、字符 Jaccard ≥0.6、编辑距离 ≤0.2）**只出候选，不自动并**；
2–3 字的中文名只认 exact + 别名表，模糊匹配关闭（张/章、伟/玮/炜 全同音）。

为什么宁可散：**错并是不可逆的**（正文被改写、事实混在一起、要逐条重排），
错分加一条 alias 边就修好了。代价不对称，所以默认宁可散。

写入时只连边、不合并；检索时展开（Elasticsearch 也是这么推荐：同义词放检索侧，改完不用 reindex）。

代词：本机 52,948 字里"他" 231 次、"她" 12 次——**"她"几乎不用**，所以别拿性别做硬约束。
代词只按"最近的人"回填，跨记忆不解（LLM 解中文零代词只有 20–30% 准确率）。

## 四·补四十九 错别字：拼音双通道是本机最划算的一条

先说反例，别再犯：**先纠错再检索**这条路是错的。ChatGPT few-shot 在 SIGHAN15 上纠错 F1 只有 36.2
（精度 26.5、召回 57.2——大量过纠错），换到 ESCpell 上专有错对只剩 10.0。
规则纠错器（pycorrector Kenlm）在 SIGHAN15 也只有 0.3147。
→ **容错只扩召回，不改 query。**

本机实测（6,000 条记忆块、2,028 字、388 个无调音节）：

- **拼音 bigram 加入召回**：同音召回 recall@5 从 0.46–0.53 到 **0.87–0.97**；
  近音 0.69–0.75 到 0.86–0.94；纯首字母 0 → **0.74–0.89**；混合噪声 0.47–0.54 → **0.79**。
- 代价：1.1ms → 18.4ms/query，索引约 3 倍。嫌慢就让拼音通道只在低分时跑。
- **无序 bigram 治换位**："记忆/忆记"同一个 key，换位 recall 0.37–0.44 → 0.72–0.75。
- **同音扩展必须限量**：2,028 字只落在 388 个音节，单音节中位 4 字、最多 38 字，77% 的字所在音节 ≥5 字。
  每字取 ≤3–5 个候选，不限量必炸。
- **删字兜底只能兜底**：把删除通道混进全局融合，正常 query 的 recall@5 从 0.893 掉到 0.730、top1 从 0.73 掉到 0.50。

别做的：对 2–4 字中文 query 直接开 fuzzy 距离 2（任意两字都能配上）、用带声调拼音、
改用户存进去的原文（记忆是证据，只能加字段或给提示）、把 jieba 分词当检索单元。

能覆盖多少：按真实分布（同音占大头）估 **75%–85% 的错字 query 能救回**，
剩 15%–25% 是音形都不近、英文混排、表情、整词记错。

方案（约 300–400 行 + 40KB 拼音表）：索引侧存原字 bigram、全拼串、首字母串、无序 bigram；
查询先跑字面，top1 ≥0.8 直接返回，不够才走拼音通道，最后按
`字面×1.0 + 拼音×0.3 + 首字母×0.2`（或 RRF）融合——**别用 max**。

拼音表用 pinyin-data（MIT，源自汉典），3,500 常用字打成 ~40KB 表，就是零依赖方案的全部外部数据。

## 四·补五十 不确定性：我们把不确定藏起来了（自己数的）

226 条里：

- **219 条（96.9%）时间置信度 <0.5**
- **126 条（55.8%）出生时间是估的**
- 但 **内容置信度 <0.5 的只有 2 条（0.9%）**

= **时间全虚、内容全硬**。系统把不确定藏起来了，她开口就必然是"确定"的语气——
这不是措辞问题，是数据没把不确定传出去。

几条有实验的：

- **口头置信度可校准**（GPT-3 自报 90% 能对上真实正确率）；RLHF 模型用话报比读 logits 准，ECE 降约一半。
- **但模型一说置信度就系统性过估**，难题上仍失灵（AUROC 0.52–0.61）→ 自报的"确定"打一折。
- **中文和德语是"确定性标记"生成最多的语言** → 中文输出天然更硬，得系统层强制加模糊词。
- **第一人称才有效**：N=404 预注册实验里，"我不确定，但是……"降信心、提正确率；
  换成无人称的"情况不清楚"，效果消失。→ **模糊句必须带"我"。**
- **中文 N=547 实验**：高不确定性降对内容与来源的信任、抬风险感知，但对话变长。
  → 模糊词是稀缺资源，只在答错代价高的地方用，闲聊别撒。
- **给出处能提信任，但给了错的、用户一核对就掉得更狠** → 只给能对上的锚点（原话/场景），不给编号和日期。

能写成规则的四条：

1. 所有不确定句必须第一人称带"我"，禁"信息不足/无法确认/据资料显示"。
2. 时间置信度 <0.5 或出生时间是估的 → **只说相对时间不报日期**（"大概是十月底那阵子"）。
3. 只记一半 → 二分句："前半截我记得：你原话是『先别动』。后面到底发没发，我这儿断了。"
4. 完全不记得 → ≤12 字 + 立刻递钩子："这个我真没印象。你提一句那阵子在弄啥，我可能就接上了。"

别做的：报百分比（"73% 把握"）、说"根据我的记忆库/检索结果"、每句都撒"可能/也许"、
给了出处又错、用"我不确定"当免责然后照样断言。

## 四·补五十一 "忽然想起"错在三处（其中一处正发生在我们眼前）

三处错：

1. **每轮必选一条**——频率写死，没有"这轮不该提"这个选项。
2. **拿相似度当触发**——相关不等于该提。RBI-Eval 用 2400 条探针证明：
   敏感旧史和"中午吃什么"语义相关，模型照样织进回答，而这不该。
3. **只给结论不给证据**——"可以顺口带一句"是叫人判断，不是给她事实。
   卡片必须存"原话片段 + 时间 + 谁说的"，缺一件不许进"忽然想起"。

**而且这轮就抓到一个现行 bug**：同一条"我给你留的最后一段话"连续好几轮被选中，
时间戳从"1 分钟前"走到"3 分钟前"——**选择器没有"已提过"这个状态**。

用户说得出的"时机不对"只有三类（14 人访谈原话）：情绪错位（人唱卡拉 OK，你提两天前的低落）、
状态过期（想喝冰的还被提醒别吃凉）、话题已关（翻篇的事被拉回）。

评分该是"收益 − 打扰成本"，不是相似度。一次打扰实测吃掉 20–25 分钟工作弧、
27% 的任务不再恢复——所以赶工、短指令、连续追问时成本拉满。

否决闸（任一为真直接不提）：话题已关、情绪反向、敏感未授权、已过期/已更新、频率超限。

过了闸再算：`S = 0.30T + 0.20E + 0.20C + 0.15F + 0.10N − 0.25R − 0.15I`
（T 话题授权、E 情绪同向、C 连续性价值、F 时效、N 新鲜度、R 敏感风险、I 打扰成本）。
**S ≥ 0.55 显式提；0.40–0.55 只隐式影响措辞、不点破；< 0.40 不提。**
权重是先验不是实测，要用"他下一两条有没有接住并延续"当标签再校准。

频率：session ≤1、同一记忆 14 天、每天 ≤2、连续两次没接冷却 7 天、他说"翻篇"就永久静音。

还有一条最容易被忽略的：**别拿记忆附和**。"过度个性化"是独立失败模式，
重复本身就是失败，不用等它不相关。

## 四·补五十二 话该说几个字，有档可查

几条硬的：

- **"嗯/对/行"不是发言，是"我在听"的信号**，不抢话轮；而且它会引导对方往哪讲。
  各自分工：同意用"对"，收到新信息用"哦"，收尾用"行/好"，纯听着用"嗯"。
  **求助和坏消息的位置禁用"哦"。**
- **轮换间隙平均约 250 毫秒**（10 种语言），人普遍避免重叠与长静默。
  而"拒绝/不同意"属于非偏好结构，会被延迟、软化、加解释
  → **同意要快而短（≤6 字），拒绝必须 ≥20 字并给理由，禁止用沉默代替拒绝。**
- **文字里的延迟不是中性的**（邮件回复延迟研究）：不用"已读不回"表达情绪，
  要停就说"我想想，晚点说"——把无限期沉默变成有期限的沉默。
- **被忽视会直接伤人，哪怕对方是机器**（网络抛球实验）。
  → 每轮至少接住对方最后一个具体点；连续两轮不接，比说错话更伤。
- **安慰要匹配可控性**：不可控的事（病、失去、别人怎么看他）→ 0 建议；
  可控的事（工作、技术、流程）→ 最多 1 条，且先问"要听我的办法吗"。
- **不请自来的建议会引发逆反**（实验：建议直接反驳对方原有选择，对方会故意反着做）；
  **越亲近越容易越界**——朋友没求助时，约 70% 的人仍然给了建议。
- **长度本身不预测亲密，"匹配对方长度"才加分**：回的字数落在对方上一轮的 0.5–1.2 倍。

五档长度：

1. **0–2 字**：只为对方明确收尾或纯确认；冲突中禁用。
2. **3–8 字**：对方在陈述/倾倒且没提问——"嗯/对/我在/然后呢"。不解释不建议。
3. **9–20 字**：有明显情绪——一句承认 + 一个具体细节，不给方案。
4. **20–60 字**：提问或求助且可控——一个判断 + 一个动作，不列清单。
5. **60–200 字**：他明确要方案/复盘——先结论后理由。

别做的：倒情绪时给三条以上建议、用"哦/嗯"接求助与坏消息、把"字数少"当目标
（短而空比长而暖更伤）、每轮都总结升华给下一步。

## 四·补五十三 被纠正：问题不是"认得不真"，是"认了没落库"

最硬的一条来自 OpenAI Model Spec 原文：模型**不得在无法核实的情况下声称删除已发生**，
且要让用户永远不必怀疑"不用记忆会不会更好"。
→ 对应我们：**没落库就说"记住了"＝违规**；落库了要给可核验回执（改成什么、旧值去哪了）。

几条该记的：

- **修正有排序**：自己改最优先，其次"给提示让对方自己改"，别人直接替他改是最重的一档。
  → 用户指错时先递台阶（"是我记串了？"），别替他定性"你记错了"。
- **中文纠正要裹缓冲**：实证里中文说话者并不比英语说话者少反驳（刻板印象是错的），
  但反驳时显著更多用缓和语。→ "我可能记岔了" + 正确值，而不是"不对，是周三"。
- **贬己只贬一档**：用"我记岔了"，不用"我太笨了"——贬过头会逼对方反过来安慰你。
- **全盘接受纠正是已被实证的失败模式**（sycophancy，五个前沿助手都有；OpenAI 还为此回滚过一次）。
  用户说"不对"要先判真假再改口；连续两次无条件认同是红灯。
- **要区分"纠正"和"更新"**：大量"被纠正"其实是用户改了口。分成四类——细节错、记反、
  张冠李戴、他自己改主意——前三类认错，第四类只更新，措辞完全不同。
- **用户一次断言 ≠ 事实**：与外部事实冲突时记成"他这么说"，不记成"事实如此"。
- **别三连道歉**：研究显示对方本来没觉得出事时，道歉反而把"没事"变"有事"。
  事实/任务型纠错不加道歉；闲聊型多一点软话是加分。

四类措辞：

1. 记错细节：「我记岔了，是周三，不是周四。改过来了。」
2. 记反了：「我把因果弄反了——是你先提的，不是我先。这条我重写了。」
3. 张冠李戴：「这事不是你的，是{某人}的。我串人了，现在拆开记。」
4. 他改主意：「你这是改主意了，还是我记错了？我按新的走，旧的标作废。」

别做的：说"你说得对"却不落库（最容易犯）、复述整条记忆来证明记得、用"我只是个 AI"免责、
在用户只是补充新信息时认错。
