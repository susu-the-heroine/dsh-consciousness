# 发版清单（照着从上往下做）


## 零、铁律：不主动发

**只有苏苏侠说"发"，才发。** 平时最多把包打出来放桌面，不许往 npm、市场、群里推。
这条是他 2026-11-15 凌晨亲口定的，写在最前面，别当流程里的第六步看。

> 为什么单写一份：这些检查散在十几个脚本里，人一忙就会漏一条。
> 2026-11-15 凌晨真的漏过——包里带着私人语料发出去三版。

## 一、改版本号

改 `package.json` 的 `version`，同时在 `CHANGELOG.md` 最上面加一节。
版本号别跳着玩：补丁位给修 bug，次位给新能力。

## 二、本地全绿（三条命令，一条都不能省）

```
node scripts/preflight.mjs      # 发包前：目录干净、没有备份文件、入口都在
node scripts/health-all.mjs     # 装好之后：库、镜像、回归、自检
node scripts/regress.mjs        # 只跑回归（改完小东西先跑这个）
```

三条都要看到「全过 / 全部通过」。任何一条红，先修，别往下走。

## 三、打包

```
node scripts/pack-split.mjs
```

生成两个包到 `桌面/识海发版/`：

- `dsh-consciousness2-<版本>-code.tgz`（代码、示例海、文档）
- `dsh-consciousness2-<版本>-embed.tgz`（模型与推理引擎）

## 四、包体检（两条）

```
node scripts/release-audit.mjs   # 包里有没有私人语料、笔记、备份残件
node scripts/pack-graph-test.mjs # 入口引到的东西，files 白名单里有没有
```

第一条要看到「当前版本干净」。第二条要看到「问题 0」。
**这两条都不许跳过**：语料泄露和缺件，都是别人装上才发现、而你在本地看不出来的。

## 五、空白机器验一遍（最重要的一步）

找一台没装过这东西的机器，或者造一个空用户目录，按 `docs/安装-离线包.md` 装：

```
node scripts/fresh-home-test.mjs   # 装机自检：建目录、建海、写读
node scripts/selftest-all.mjs      # 新机器上应是「通过 + 跳过」，没有失败
```

要看到：装机自检全过；一键自检「失败 0」，跳过的那几组名字列出来。
**新机器上出现任何一条"失败"，都不许发。**

## 六、发布（人来做）

- npm：`npm publish`（这台机器没装 npm，用别的机器或让他自己来）
- 市场页：确认页面上显示的版本号跟 `package.json` 一致。
  页面上写着 0.3.7、包里是 0.4.8，等于修的全没发出去。

## 七、发完回验

装上发布版，跑一次 `node scripts/health-all.mjs`；
再打开侧边栏看金圈「识」在不在。两样都对，这一版才算完。

## 出事了怎么退

删掉插件目录、把 profile `package.json` 的 `dsh.profile.bundles` 里那行名字去掉，重启。
记忆在 `~/.dsh/consciousness-seas/`，跟插件分开，不会跟着没。
