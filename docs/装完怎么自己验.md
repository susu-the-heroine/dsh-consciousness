# 装完怎么自己验

不用终端，不用记命令。装完照这五步走，出问题知道卡在哪一步。

## 一、先看它有没有被宿主认出来

打开插件管理页，找到「识海」这一条。

- 状态是「正常」或「已启用」，往下走。
- 状态是「异常」，点开看原因。最常见的一句是 `failed to read overlay ... cordis.patch.yml`：
  意思是插件包里少了 `cordis.patch.yml`。这个文件在插件根目录，五行，内容是插入一个
  `id: consciousness`、`name: dsh-consciousness2`、`enabled: true` 的组件。少了就补回去。
- 显示「不包含任何组件」，也是同一个原因。

## 二、看它有没有进上下文

随便发一句话，然后把这一轮的上下文展开，找 `【识海 · 记忆上下文】`。

- 有这一段，说明注入通了。
- 没有，先重启一次 DSH 再看。还是没有，去 `~/.dsh/consciousness-audit.log` 看最后几行有没有
  `inject-mount`；一条都没有，就是插件压根没加载，回第一步。

## 三、看它记不记事

说一句具体的小事，比如「我家猫叫豆豆，三岁」，等十几秒，再问「我家猫叫什么」。

- 答得出，记忆链路通。
- 答不出，去 `~/.dsh/consciousness-seas/<海名>/raw/` 看最新的 `.jsonl` 里有没有你刚才那句。
  没有就是没写进去，有就是检索没命中。

## 四、看它忘不忘

隔一天再问同一件事。记得就说明还在，变淡是正常的（它会按被想起的次数衰减），
「忘了」也是设计的一部分，不是坏了。

## 五、看数据在哪、怎么拿走

- 记忆：`~/.dsh/consciousness-seas/<海名>/data.json`
- 原始消息：同目录 `raw/*.jsonl`
- 备份：`~/.dsh/consciousness-backups/<海名>/`
- 风格观察：`~/.dsh/consciousness-style.json`（默认关，开了才有）
- 自我条目：`~/.dsh/consciousness-self-notes.json`
- 风格熔断记录：`~/.dsh/consciousness-style-cost.json`

想搬走，整目录拷 `consciousness-seas` 即可；想只要文本，用「把记忆拿走」那节说的导出。

## 六、真出事了怎么办

按这个顺序，别跳：

1. 先卸载插件，确认消息能发、历史能加载。**先让 DSH 回到能用状态**，再谈修。
2. 看 `consistency-load-error.txt`、`consciousness-audit.log` 最后几十行。
3. 插件目录里 `lib/` 下的文件是源码，改错了就整份退回去（`_backups/` 有备份）。
4. 别在插件卡住的时候反复重启——它会一直卡在同一步。

## 一句话

装完只验三件：认出来了、进上下文了、记得住。三件都过，剩下的是调，不是坏。
