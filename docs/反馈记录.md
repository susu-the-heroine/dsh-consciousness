# 反馈记录

收到的反馈，一条一行。**这是给我们自己看的，不是给提反馈的人填的。**

规矩：别人肯开口就够了，不要求他按格式写。系统、版本、报错、结论，我们自己问、自己补。

---

## 格式

| 日期 | 谁 | 版本 | 系统 | 反馈原话 | 判断 | 处理 |
|---|---|---|---|---|---|---|
| | | | | | | |

判断那栏只写三种：`bug`（装不上/跑不动）、`建议`（功能想法）、`误用`（不是 bug，是用法不对）。

**版本那栏的硬规矩**：问得到就写，比如 `0.4.0`；问不到就写 `未确认`。

**不许猜。** 猜出来的版本会让人拿着错的线索去查，比空着更坏。

想确认他装的是哪一版，最稳的办法是让他报装的那天的日期，对着 npm 上的发布时间倒推；**或者让他打开侧栏那个金圈，看里面有没有写版本号。**

问不出口也没关系，`未确认` 就 `未确认`，先把反馈留下，版本以后能补。
