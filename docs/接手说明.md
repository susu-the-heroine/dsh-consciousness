# 接手说明 · 被掐断之后从这里接着干

> 这份是给「这个窗口被上游判成拒绝、目标被挂起」之后用的。
> 出了那种事，先看这里，别凭记忆猜读到哪了。

## 一、被掐断了怎么接

1. 界面会显示「本轮运行失败 DeepSeek Messages stream: unsupported stop reason refusal」、目标变「已暂停」。
2. 那不是代码错，是上游那段话被判定成拒绝，整轮断了，目标被系统挂起。
3. 挂起的目标只认**人**的话恢复：你说一句「继续」就行，我自己按不动那个开关。
4. 恢复后第一件事不是回忆，是跑：

   ```
   node scripts/audit-next.mjs 5
   ```

   它会按账里写过「逐行嚼：xxx」的记录算出**还剩哪些份**，按行数从大到小列出接下来五份。这是唯一可信的「读到哪了」。

## 一之半、闹钟（定时任务）该怎么做——写给以后的我看

闹钟每二十分钟醒一次。醒来照这个顺序，一步都不许跳：

1. **先数活**：`node scripts/audit-next.mjs 1`
   - 报「还剩 0 份」＝活干完了：**先删掉这条提醒**，回一句「审计读完，提醒已撤」，收工。不许建目标，不许读文件。
   - 还剩 1 份以上：往下走。
2. **写心跳**：`node scripts/heartbeat.mjs "闹钟起来了，还剩 N 份"`。
3. **管目标（只在这时候才管）**：
   - 活着、装了引信：不动。
   - 活着、没装引信：`resume` 一次。
   - 被按成「暂停」、`resume` 也被拒：把旧目标 `complete` 退掉，再 `create_goal` 建新的（objective 抄旧那句，max_goal_rounds 给 900）。建不成别反复试，直接干这一轮的活。
   - **铁律：还剩 0 份时，退目标、建目标一律不许做——没活就不建目标。**
4. **干这一轮**：按 audit-next 报的那一份读、能复现的才改、改完记账、结尾报「读到哪了」。一轮只干一份。

为什么要有第 3 步：目标被系统按成暂停之后，只有人能恢复；夜里断了没人按，活就停在原地。退掉再建是唯一能自己爬起来的路。但这条路只能用在**还有活**的时候——活干完了还建，就是白烧 token。

## 二、进度存在哪

- `docs/问题总表-1119.md` —— 唯一的进度凭据。每份读完/改完都追加一段，末尾一句「读到哪了：文件+行号区间+下一份」。
- `docs/审计进度.json` —— 脚本算出来的快照（份数、剩余行数、接下来二十份）。跑 `node scripts/audit-next.mjs --write` 刷新。
- 判进度只认「逐行嚼：」这个标记。文件名字在账里出现过不算读过——这一晚就是这么把「只剩两份」报错的。

## 三、每轮的规矩（不变）

1. 一次只读一份文件里的连续 60–120 行；开新文件先报它的总行数。
2. 可疑处先记；能复现的才动手；一次只改一处。
3. 改前备份到 `_local-backups/`，改后 `node --check`，再跑相关测试（从 `C:\` 跑，证明不依赖当前目录）。
4. 跑不过就回滚，并把原因写进账。
5. 每条修完在账里记一行：文件+行号、症状、复现、改后数字。
6. 结尾必须报「读到哪了」。

- 不换语义模型，不拆巨型函数，不合两套锁。
- 真库只读，测试只碰沙箱海。
- 不许拿「上下文档位」当停工理由。
- 判据：370 题头名 ≥94.5、前十 ≥97.0、否定题 41/41、陌生海 12/12、自检 121 组不新增红。

## 五、防止再被掐断的几个做法

1. **一回只干一件事**：读一份、或改一处，不在同一轮里堆太多输出。
2. **结论写文件，不写聊天**：长清单、长数据都落到账里或 json 里，聊天里只报数字和结论。
3. **不复制大段原文**：引用只给行号和短句，避免把整份源码贴进对话。
4. **报下一份前先跑脚本**：`audit-next.mjs` 说哪份就是哪份，不靠记忆。
5. **轮数留余量**：目标轮数上限不要顶到边，快用完就提前续。

### 那把「锁」到底是干什么的（给接手的人看的人话）

- 库是一个整份的 `data.json`。两个人同时往里写，后写的会把先写的整段盖掉——锁就是防这个。
- 做法：写之前先在同一个目录建一个 `data.json.lock`，谁建出来谁拿到，另一个就等（等不到就宁可不写，会记 `write-sea-lock-refused`）。
- 撒手：写完把这个文件删掉。删的时候可能撞上 Windows 的「还没删干净」，所以现在会重试三次，三次都不行记一笔 `write-lock-release-failed`。
- 牌留在盘上会怎样：后面的人白等几秒到一分钟；等久了过期判据会把它当成「自己的过期牌」，然后清掉重来（审计里 `write-lock-self-stale`）。
- 边界：只管同一台机器上的多个进程。两台机器挂同一个库同时写，这把锁看不见对方——那种要真数据库。
- 2026-11-21 修的正是「撒手不干净」：`mutateSea`（改一条）原来不重试、失败不吭声；五处撒手现在统一。
